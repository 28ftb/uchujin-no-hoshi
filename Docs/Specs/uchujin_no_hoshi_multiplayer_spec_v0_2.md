# 『宇宙人の星』マルチプレイシステム仕様案 v0.2（統合版）

- 作成日：2026年10月15日
- 対象：『宇宙人の星』の星訪問・共同生活・通信・セーブ・星間交流
- 文書種別：企画・ゲームデザイン仕様案（実装確定書ではない）
- 関連仕様：ワールドシード／村・マップ、宇宙語・辞書・タブレット、住民生活、農業、釣り、鉱山、生き物50種類、商店、クエスト、家・家具、料理・加工、時間・天候、ロケット帰還

> **中核コンセプト**：それぞれ異なる星で暮らすプレイヤーが互いの村を訪れ、協力し、品物・宇宙生物・発見・思い出を持ち寄る。友達の行動もその星の住民の生活と歴史に残る。

## 0. 本書の位置づけと確定度

この仕様書は、これまでのマルチプレイ案 v0.1〜v0.2 を一つにまとめたもの。既存の他システムで決まっている点と、今回のマルチプレイ設計で提案している点を混同しない。

- **【既存確定】**：関連企画ですでに明確に決まっている前提。
- **【既存方針】**：他システムや直前の検討で維持する方針。
- **【採用推奨】**：本書の基本設計として強く推すが、最終決定ではない。
- **【追加提案】**：遊びの拡張案。採否や細部は未確定。
- **【未決定】**：今後の設計・調整を必要とする点。

**既存の重要前提**：

1. 星ごとにワールドシードがあり、地形・村・初期住民・宇宙語などが変わる。
2. 宇宙語の語彙・語順・文法は星のシードに依存し、各プレイヤーが自力で推理・記録する。
3. **訪問者へ辞書を自動配布しない**。渡すかどうか、どの範囲を渡すかはプレイヤーの自由。誤った推測や意図的な嘘も共有可能。
4. 住民は実際に生活し、購入品を使い、引っ越し、ほかの住民やプレイヤーとの関係・記憶を積み重ねる。
5. 主要な生活コンテンツは農業・釣り・鉱山・宇宙生物取り・クエスト・セルフ販売の商店。
6. 宇宙生物は既存の約50種類を中心に、農業・料理・加工・生活に能力を活かす。
7. 主人公の商店は **店番やレジ打ちを必要としないセルフ販売** を維持する。
8. 四季は設けない。時間・天候は星とその時点の状況に応じて変わる。
9. **鉱山は日付変更時、プレイヤーが中にいても即座に鉱石を再配置する。目の前で現れたり消えたりしてよい。**
10. 物語の主目標は壊れた宇宙船を修理して別宇宙の故郷へ帰ること。最後の出発は「最後の引っ越し」として位置付ける。

## 1. マルチプレイの目的・体験

### 1.1 目指す面白さ

- **星を訪ねる**：自分とは地形・住民・気候・宇宙語が違う世界に入る。
- **一緒に暮らす**：農場、鉱山、釣り、料理、商店、家づくりなどの既存の遊びを協力して行う。
- **知識を分け合う**：宇宙語辞書、マネピの音声カード、生物の観察、地図や料理のメモを任意に共有する。
- **星同士をつなぐ**：アイテム、家具、宇宙生物、料理を持ち寄り、交換し、販売する。
- **思い出が残る**：ゲストが贈った家具、植えた作物、住民との出会いや交流が星の履歴として続く。

マルチ専用の別ゲームを増やすより、**ソロの生活システムに本当の友達が加わる**ことで面白くなる構成を基本にする。【採用推奨】

### 1.2 マルチプレイで変えないもの

- プレイヤーの宇宙語を勝手に正解翻訳しない。
- 辞書共有を強制しない。
- 友達がいることを理由にソロの全機能を使えなくしない。
- 店番や手動接客を強制しない。
- マルチで鉱山の「突然の鉱石再配置」を延期しない。
- マルチ専用の攻略必須要素を無理に導入しない。

## 2. 参加形式：観光・お手伝い・共同生活

**【採用推奨】** 3つの遊び方を、別のワールドモードではなく、同じ星への参加権限・滞在方法として扱う。

| 遊び方 | 想定する遊び | 星に残るもの |
|---|---|---|
| **観光・訪問** | 村を歩く、住民と話す、釣り、買い物、探索、交流 | プレイヤーとの出会い、贈り物や購入などの出来事 |
| **お手伝い** | 農業、採掘、素材収集、料理、建築・修理への協力 | 作業結果、クエストへの貢献 |
| **共同生活** | 継続して同じ星に住み、個人の家・収納・住民との関係を築く | 家具・住居・畑・生物など、長期的な生活の痕跡 |

- 観光のつもりで訪問し、何度も来るうちに共同生活へ発展してよい。
- 共同生活者でも、毎回ホストと同じ行動をする必要はない。
- 友達の星に家を建てず、ゲストとして遊び続けてもよい。
- 自分の星を持ちながら、友達の星にも家や生活基盤を持てる案を検討する。【追加提案】

### 2.1 対応人数

- **1〜4人**：初期検討用の仮人数。【未決定】
- **6〜8人**：村の規模、住民AI、同期量、画面設計と合わせて検討する余地。【未決定】
- 「4人が確定上限」とはしない。

## 3. ワールドとプレイヤーの基本関係

### 3.1 ワールドシードとワールドID

**【採用推奨】** 星には少なくとも2種類の識別情報を持たせる。

- `WorldSeed`：初期のマップ、宇宙語、地形、住民構成、気候などを生成する元データ。
- `WorldId`：実際に生活が積み重なっている個々の星（セーブ）の固有識別子。

同じシードでも、別々に始めたセーブなら別の世界。ある星で住民が引っ越したり、家具を置いたりしても、別セーブには反映されない。

訪問先の辞書・地図・住民記録は **WorldId ごと**に区別する。言語の再現にシードを使っても、観察履歴や住民の出来事まで別星と混ぜない。

### 3.2 星の管理者と参加者の違い

| 立場 | 意味 |
|---|---|
| **星の管理者／ホスト** | 星のセーブを持ち、ワールドを起動・管理する人 |
| **共同居住者** | 星の中で継続して暮らし、所有物・住民との関係を持つ参加者 |
| **訪問者** | 自分の持ち物を持って星へ遊びに来る参加者 |

**星の管理者＝星で暮らせる唯一の主人公**とはしない。共同居住者も家づくり・住民交流・農業などを通常の生活として行えるようにする。【採用推奨】

### 3.3 ソロとマルチの共存

- ソロで育ててきた星をそのまま友達に開放する。【採用推奨】
- 友達が帰れば、同じ星の状態でソロに戻る。
- 新しく作った星に、開始直後から友達を呼んでもよい。
- マルチ用に別の農場や別の宇宙語を作り直さない。

## 4. 星への参加・再訪問・退出

### 4.1 参加の基本フロー【採用推奨】

1. ホストが、自分の星をソロまたは招待可能な状態で起動する。
2. 友達を招待する。参加者は同じ星のワールドIDへ接続する。
3. ゲストは星の地形と現在の村の状態を受け取る。
4. ゲスト自身の持ち物・同行生物・辞書・探索記録を読み込む。
5. その星での出会い・関係・所有スペースがある場合は復元する。
6. 参加後は移動、交流、農業、釣り、採掘、料理などを行える。

### 4.2 途中参加

- ホストが開始済みの世界へ途中参加できる。【採用推奨】
- 住民の現在位置、天候、農場、家具、商店、鉱山など**現在の状態**から参加する。
- ゲスト参加時に住民の行動や日付を巻き戻さない。

### 4.3 退出・再訪問

- ゲストは自分の携帯品と、同行設定の宇宙生物を持って帰る。
- 星に設置した家具、個人部屋、預けた生物、委託商品などはその星に残る。
- ホストがその後も遊べば、住民・作物・商店・預けた生物の状態が変化する。
- 再訪問時は、以前の住民との関係や所有スペースを引き継ぐ。
- **ホストがゲームを閉じている間、星の時間や商店販売が自動で進むことは基本的にない。**【既存方針】

### 4.4 ホスト不在の共同生活

- 基本方式ではホストが星を起動している必要がある。【採用推奨】
- 共同居住者がホスト不在でもワールドを起動できるかは【未決定】。
- 実現する場合は、ワールドセーブの共有・正本管理・ホスト交代が必要。通常の「ロビー主催者の移行」とは別の機能として扱う。

## 5. どのデータが星に属し、どれが個人に属するか

**【採用推奨】** 星の永続世界状態と、プレイヤー固有の携帯資産・知識を区別する。

| データ | 基本的な管理先 | 備考 |
|---|---|---|
| 地形・道路・橋・施設・家屋の配置 | 星のセーブ | 生成初期値＋生活後の変更 |
| 星の宇宙語・文法・発音規則 | 星のセーブ／ワールド生成情報 | プレイヤーの翻訳とは別 |
| 日付・時刻・天候 | 星のセーブ | ホストが進行を管理 |
| 住民の居住状況・予定・記憶・人間関係 | 星のセーブ | プレイヤー別の関係も同じ星で管理 |
| 農場・収穫物・商店棚・売上 | 星のセーブ | 商品・区画の所有者記録を持つ |
| 鉱山の鉱石 | 星のセーブ | 日付変更時に即再配置 |
| 星に置いた家具・設備・収納 | 星のセーブ | 個人所有や共有の属性を持つ |
| 星に預けた宇宙生物 | 星のセーブ | 元の飼い主情報を保存 |
| プレイヤーの携帯品・お金 | 各プレイヤー | 携帯可の資産。通貨ルールは未決定 |
| 同行中の宇宙生物 | 各プレイヤーを基本 | 星に預ける場合は所有状態を移す |
| 宇宙語辞書・仮訳・個人のメモ | 各プレイヤー | 星ごとに独立管理 |
| 個人の地図探索履歴・写真 | 各プレイヤー | 必要なら共有可能 |
| 委託販売品・未精算売上 | 委託先の星 | 委託者IDと取引履歴を持つ |

**検討上の注意**：P2Pの実際の永続化方法は設計が必要。上記は「ゲーム上の所有・責任の分け方」を表しており、通信ライブラリが自動で保存を保証するという意味ではない。

## 6. 所有権・共有スペース・権限

### 6.1 アイテムの基本区分【採用推奨】

1. **個人の携帯品**：本人が持つ道具、魚、鉱石、料理、持参した家具など。
2. **星に設置された物**：畑、住宅、家具、かまど、商店の棚など。
3. **預けた個人所有物**：個人収納の中身、預けた宇宙生物、委託販売品など。

持ち帰れるかどうかは、物の「カテゴリ」だけでなく、**誰が所有し、置かれた状態か**によって判断する。

### 6.2 操作権限の3段階【採用推奨】

| 権限 | イメージ |
|---|---|
| **観光** | 村の見学、交流、許可された釣り・買い物・探索など |
| **お手伝い** | 畑仕事、採掘、料理、素材集めなどを幅広く協力 |
| **共同生活** | 家具・農場づくりなど、継続した生活基盤の編集も行える |

- 実際の許可範囲はホストや区画の所有者が決める。
- 細かな許可を大量に強制せず、基本段階＋必要な場所の個別設定を用意する。
- 「農場は編集できるが、自宅の家具は動かせない」などを実現できるようにする。【追加提案】
- 信頼する友達とすべて共有したい場合は、そのまま広い権限を与えられる。

### 6.3 所有者の判定

- 野生の魚・鉱石などは、原則として実際に取得したプレイヤーの持ち物とする案。【採用推奨】
- ほかのプレイヤーの**畑の作物**は、収穫作業者へ自動で所有権を移さない。
- 畑や収納に共有設定があれば、その範囲内で利用・持ち帰りを許可する。
- 住民の家の家具や、飼い主のいる宇宙生物は、譲渡などの操作を経ずに自由持ち帰りとしない。

## 7. 農業の協力

### 7.1 できること【採用推奨】

- 複数人で耕す、種をまく、水やり、収穫を同時に行う。
- 個人で持ち込んだ種を使える。
- 共同農場を分担して育てられる。
- 共同農場と個人区画を両方作れる。【追加提案】
- 農業用宇宙生物を連れてきて、ホストの生物と協力させられる。

### 7.2 収穫物の帰属

**【採用推奨】** 共有農場や他人の農場で収穫したものは、基本的にその農場が指定する収納へ入れる。権限があれば収穫した人が持ち帰ることも可能。

「手伝っただけで農場の全作物がゲストに移る」仕様にはしない。一方、共有したい人の自由も残す。

### 7.3 宇宙生物の共同作業

- 例：ホストのモギモギが収穫し、ゲストのハコバチが運搬する。
- 例：ゲストのミズプクが畑へ水を供給する。
- 既存の生物が備える能力を共通ルールで適用し、マルチだから別能力にしない。
- 生物の移動・作業対象・効果は、同じ星の状態として同期する。

### 7.4 ゲスト退出後

ゲストが植えた作物は星に残り、ホストがその後ソロで遊べば成長する。後日にゲストが再訪すれば、自分が作業した畑の変化を見られる。

## 8. 鉱山の協力

### 8.1 基本

- 鉱山は既存方針どおり **10階層程度**。深いほど価値の高い鉱石が現れる。
- ツルハシは鍛冶屋で段階的に強化する。
- 複数人が同じ鉱山・階層へ入り、一緒に採掘できる。【採用推奨】
- 強いツルハシを持つ人が硬い鉱石を採掘し、素材をほかの人へ渡せる。

### 8.2 日付変更【既存確定】

- 日付変更時、現在の鉱石が消え、新しい鉱石が再配置される。
- **プレイヤーが鉱山内にいても延期しない**。
- **複数人が鉱山にいても例外なし**。
- **目の前で突然出現・消滅して構わない**。この星では通常の自然現象として扱う。
- 新しい鉱石は、その場にいる全プレイヤーに同じ配置で見える。

### 8.3 同時採掘

- 二人が同じ鉱石を狙った場合、ホストが採掘成立と獲得者を確定する。【技術上の推奨】
- 通信遅延により一つの鉱石から重複取得しないよう処理する。
- 再配置の瞬間に採掘していた場合の結果は、日付更新順序を定めて一貫して処理する。【要詳細設計】

## 9. 釣り・宇宙生物取りの協力

### 9.1 釣り

- 一緒の川、池、海で釣りを楽しめる。
- 魚の大きさ・品質・珍しさを見せ合える。
- 釣り名人の実演を複数プレイヤーで観察できる。
- 協力したり、個人的な釣果を競ったりする遊び方は自由。
- 魚の釣り上げ結果や水中の対象状態は同じ世界で整合するよう管理する。

### 9.2 生き物取り

- 約50種類の宇宙生物が既存仕様どおり生息する。
- 生息分布は星のマップ・気候・時間・天候などで変化する。
- 複数人で捕獲準備、誘導、観察を分担できる。【採用推奨】
- 捕まえた生物を交換、プレゼント、別の星へ同行させることができる案。【採用推奨】
- 同じ野生生物を二人が同時に捕獲した場合の確定処理を用意する。

### 9.3 生物図鑑

- 捕獲した星、場所、日付、飼い主など、実際に経験した情報を記録する案。
- 友達の発見情報は、本人の意思で共有する。未観察の情報を勝手に完全開示しない。

## 10. 宇宙生物の星間移動：同行・預ける・譲る

**【追加提案・重要】** 生物の移動を3種類に区別する。

| 操作 | 状態 | 星退出時 |
|---|---|---|
| **同行** | 自分の生物を連れて訪問先で生活する | 自分と一緒に元の持ち物へ戻る |
| **預ける** | 元の飼い主のまま、友達の星に住み、そこで働く | 訪問先に残る |
| **譲る** | 受け取ったプレイヤーに所有権を移す | 新しい飼い主の生物になる |

### 10.1 同行

- 連れてきたポカリスやミズプクを農業・料理・加工に利用できる。
- 帰還時は同行させる。ただし、本人が別の操作で預ける・譲る選択をした場合はそれを優先する。

### 10.2 預ける

- 友達の星に生物が実際に残り、農業や料理に参加する。
- ホストが遊んでいる間は、預けた生物もその星の時間に従い生活する。
- 持ち主が再訪したときに会える。
- 預けている生物を、所有者の元の星で同時に働かせない。
- 引き取り、飼育枠、作業許可の細部は【未決定】。

### 10.3 譲る

- 相手へ正式に所有権を移し、相手が連れて帰ったり飼育したりできる。
- 捕獲場所・育成履歴・教わった調理技術など、個体としての記録を引き継ぐ案。【採用推奨】

### 10.4 生物の固有ID

- 星間移動・預かり・譲渡を扱うため、一匹ごとに識別子を持たせる案。【技術推奨】
- 交換失敗で同じ生物が両方に残ったり、両方から消えたりしないよう取引記録を管理する。

## 11. 料理・加工の協力

### 11.1 宇宙生物と調理具の融合【既存方針との連携】

- 宇宙生物が熱・水・回転・乾燥・発酵などの能力を提供する。
- 生物そのものが調理器具の役割を果たしたり、専用の設備と一体になったりする。
- 複数の生物を組み合わせることで、新しい調理・加工ができる。

### 11.2 マルチでの分担

- 例：Aがポカリスで火力調整、Bがミズプクで給水、Cが材料準備。
- 例：ゲストの新しい能力を持つ生物とホストの生物を組み合わせ、初めての料理を作る。
- 調理した料理は食事、贈り物、セルフ販売の商店の商品にできる。
- **一人でも料理・加工が成立する**ことは保つ。複数人なら操作分担・同時加工・試行錯誤が増える構成。【採用推奨】

### 11.3 工房・加工室

- 家や庭に調理用生物の住み場所と加工設備を自由配置する。
- 共同キッチン、個人の料理室、共有素材置き場などを作れる。【追加提案】
- 加工中はその星のゲーム時間で進み、持ち主が不在でもホストが遊んでいれば進行する。

## 12. 商店・直接交換・委託販売

### 12.1 商店の前提【既存確定】

- 商品を棚に並べ、価格を付け、住民が自分で選んで購入する。
- プレイヤーは店番・レジ業務をしない。
- 売れた商品と住民の購買行動は、星の生活状態へ反映する。
- 商店のマネピは、住民が預けた声や反応を再現できる。書き置きの宇宙文字を主人公が読めることにはしない。

### 12.2 取引方式【採用推奨／追加提案】

| 方式 | 内容 | 扱い |
|---|---|---|
| **直接交換** | プレイヤー同士で品物を交換 | 採用推奨 |
| **直接販売** | お金と品物を交換する | 採用推奨 |
| **プレゼント** | 品物を無償で渡す | 採用推奨 |
| **商店に寄贈** | ゲストの商品をホスト商店のものとして並べる | 追加提案 |
| **委託販売** | ゲストの品物を商店へ預け、住民へ販売する | 重要提案 |
| **共同販売** | 複数人が集めた商品を共同の店で売る | 追加提案 |

### 12.3 委託販売の一例【追加提案】

1. ゲストが別の星で作ったジュース20本を持参する。
2. ホスト商店に預け、商品の種類・数量・販売価格を記録する。
3. ゲストは自分の星に帰る。
4. ホストが遊んでいる間、住民が商品を購入する。
5. 売れた数・未販売数・未精算売上をホストの星に記録する。
6. ゲストが再訪した際、売上や売れ残りを受け取る。

**重要**：P2Pのホスト不在中にオンライン市場だけ常時進行する仕様にはしない。委託者が不在の間に各個人セーブを書き換えることも前提としない。

### 12.4 星の需要差

- 同じ商品でも、初期住民・個性・食文化・気候によって売れ行きが変わる。
- 自分の星で不人気な料理が友達の星で人気になる可能性がある。
- 住民が買った品物は、実際に自宅で使ったり食べたり、ほかの住民へ贈ったりする。
- マネピの伝言や生活観察を通して、星ごとの需要や宇宙語を推測できる。

### 12.5 通貨と価格【未決定】

- 星をまたぐ取引のために**共通通貨**が使いやすいという提案がある。
- 星ごとの独立通貨、為替、税、委託手数料などは確定していない。
- 不必要な価格上限・回数制限を最初から設ける前提にはしない。

## 13. 宇宙語辞書のマルチプレイ

### 13.1 絶対に維持する条件【既存確定】

1. 宇宙語は星ごとに異なる。
2. 訪問先の宇宙語を、その星の住民全員が話す。
3. **訪問しただけでは辞書が自動配布されない。**
4. 翻訳はプレイヤーの推測であり、ゲームが勝手に正解へ書き換えない。
5. 共有する辞書やメモには誤解や嘘が含まれていてもよい。
6. 辞書を持たない友達も、観察・身振り・行動の手掛かりを使って生活・交流できる。

### 13.2 任意共有の種類

| 共有物 | 共有内容 | 位置づけ |
|---|---|---|
| 辞書全体 | 自分の仮訳・メモをまとめて渡す | 既存方針 |
| 選択単語・ページ | 一部だけ教える | 既存方針 |
| 発話の音声カード | 原音・発音表記・話者・状況などの観察記録 | 拡張提案 |
| 例文や発言記録 | 自分で収集した証拠を渡す | 拡張提案 |
| 地図・地名メモ | 場所の説明や自分の仮の呼び名を渡す | 拡張提案 |
| 写真・観察メモ | 生物や家具・住民に関する見聞を渡す | 拡張提案 |

### 13.3 正誤は共有時に判定しない

- Aの「モルカ＝おいしい」、Bの「モルカ＝好き」という解釈を並べて比べられる案。
- どちらかをゲームが自動で採点しない。
- 共有後も自分の原メモを保てるよう、比較・コピー・追記を選べる案。【追加提案】
- 「誰から受け取った情報か」を表示する案。【追加提案】

### 13.4 マネピと共同解読

- 住民がマネピへ託した発話を、プレイヤーが再生・比較する。
- 例：店の価格を変え、来客の声と表情を比べる。
- 例：同じ住民へ異なる食感の料理を渡し、発言を記録する。
- 例：住民が宇宙生物へ調理指示を出す場面を観察する。
- 友達がそれぞれ違う仮説を立て、別々の実験を担当できる。
- **マネピは住民が預けた言葉や反応を再現する**。勝手な盗聴機として扱わない。

### 13.5 訪問先ごとの辞書

- 他の星の辞書は WorldId ごとに分けて保存する。
- 同じ音でも別の星では意味が違う可能性があるため、知識を勝手に混合しない。
- 辞書の表示・検索・書き込みは、プレイヤーごとのタブレットで行う。

## 14. 住民AI・関係・記憶のマルチ化

### 14.1 プレイヤー別の認識【採用推奨】

住民はホスト・ゲストを別人として覚える。

- 初対面か、何度も会っているか。
- 誰からプレゼントをもらったか。
- 誰と一緒に釣り、料理、農作業などをしたか。
- 誰がクエストを手伝ったか。
- いつ最後に会ったか。
- 誰と住民の家で交流したか。

あるプレイヤーに親しげでも、別プレイヤーには初対面の反応をする。住民の趣味・性格・記憶・行動は、星の共通世界の中で一貫させる。

### 14.2 住民同士の変化にもつながる

- ゲストが二人の住民を主人公の家に招く。
- その場で会話し、二人の住民の関係が変化することがある。
- ゲストが帰った後も、住民二人が仲良く出かけるようになるかもしれない。
- ゲストが贈った家具が住民の家に残り、そこで使われ続ける。

### 14.3 住民の引っ越し

- ホストがソロで遊んでいる間にも引っ越しや新住民の入居が起こる。
- ゲストが前回会った住民は、次の訪問時には村にいないことがある。
- 住民辞典の記録は残る。
- マネピ経由の便りや再訪などは、既存の住民生活案と連携させる。

### 14.4 ゲスト参加時の会話

- プレイヤー同士が同じ発話・住民の行動を観察できる方式を推奨。
- 発言の意味は自動共有しない。
- 住民の会話中、ほかのプレイヤーの行動や時間を一律に停止する必要はない。
- 同じ住民へ同時に話しかけた場合の会話参加・割り込み仕様は【未決定】。

## 15. クエスト・公共施設・個人の経験

### 15.1 星共通の出来事と、個人の関係を分ける【採用推奨】

| 出来事 | 主な進行 |
|---|---|
| 橋・公共施設を建設する | 星に一度だけ完成し、その後は全員が利用 |
| 住民の引っ越し・生活上の出来事 | 星の住民シミュレーションとして進行 |
| 個人的な贈り物・親交 | 受け取った住民と、渡したプレイヤーの関係に反映 |
| 食材・魚・鉱石の納品依頼 | 複数人で材料を集め、手伝った人物も記録 |
| ロケット修理 | 該当する星のストーリー上の進行 |
| 宇宙語解読 | 各プレイヤー自身の辞書上の進行 |

### 15.2 共同貢献

- Aが木材、Bが鉱石を持ってきて橋を修理する。
- 橋は星に一つ完成する。
- 住民は協力した人物をそれぞれ覚えられる。
- 後から来たゲストは完成済みの橋を見る。過去の世界イベントを無理に初期化しない。

### 15.3 取り逃した出来事

- 後から参加したプレイヤーは、今の村をそのまま経験する。
- 過去に起きた出来事は、住民の会話・家具・写真・マネピの伝言・他プレイヤーの説明から知ることができる。
- 個人の辞書に過去の正解が自動で埋まることはない。

## 16. 家・家具・共同居住

### 16.1 共同生活の住空間【追加提案】

- 同じ家の個人部屋に住む。
- 星に自分の小さな家を建てる。
- 共同住宅で暮らす。
- 家を持たず短期滞在する。

これらをできるだけ自然に選べるようにする。建てられる土地・家の最大数・部屋数は【未決定】。シードで地形が変わるため、配置は地形と村の区画に従う。

### 16.2 家具利用・所有

- 訪問者も許可された家具で座る、食事、演奏、観察などができる。
- 家主の許可があれば共同模様替えをできる。
- 他人の家具を移動・持ち帰るには、その所有者の許可が必要という案。
- 別の星で買った家具を持ち帰り、自分の家に飾れる。
- 家具の入手元や贈り主の記録を残せる。【既存家・家具案との連携】

### 16.3 宇宙生物の住み場所

- ゲストの同行生物が家の家具を利用できる。
- 預けた宇宙生物はその星に住み、農業や調理を手伝える。
- 生物用の寝床や池・巣箱などは、既存の家具・庭システムと共有する。

### 16.4 個人と共有の収納

- 共有倉庫、個人収納を用意する案。【採用推奨】
- 自分の家の品物を守りながら、素材を共有したいときは共有できる。
- どこに保管したか、今どの星にあるかが分からなくならない表示を検討する。

## 17. 地図・写真・発見の共有

### 17.1 星ごとの探索

- 訪問先の地図は、初めからすべて完成している必要はない。【採用推奨】
- 各プレイヤーが探索した場所や、自由に付けた地名を記録する。
- 建物や生息地を観察してメモできる。
- 宇宙語の地名が読めることを前提にしない。

### 17.2 共有案【追加提案】

- 地図の場所をピンで教える。
- 写真を渡す。
- 自分が付けた地名・説明を共有する。
- 観察した宇宙生物の生息地を教える。
- 地図全体を押し付けず、必要な範囲だけ伝える。

例：友達が「光る池」と呼んでいる場所の写真だけを受け取り、位置を教わらず探してみる遊びも成立する。

## 18. 時間・天候・睡眠

### 18.1 共通時間【既存方針】

- 星にいる全員が同じゲーム内日付・時刻を共有する。
- その星の気候・天候を共有する。ただし地形による局地的な天候差の案は維持する。
- 一人がタブレットを開いても、マルチ全体の時間は停止しない。
- 住民・作物・生物・加工・商店は星の時間に従って進行する。

### 18.2 個人睡眠【採用推奨】

- 一人だけ眠った場合、休息・回復を行える。
- その操作だけで他人の時間を翌朝へ飛ばさない。
- 全員が同意すれば、指定された朝まで時間を進める方式を基本案とする。
- ホスト優先スキップ等の追加設定は【未決定】。

### 18.3 日付更新【既存確定】

- 睡眠とは独立して日付が進む。
- 鉱石再配置を含む日付更新は、鉱山内の人数・位置と無関係に実行する。
- 農場・住民予定・加工完了・商店の日別集計なども整合して更新する。
- 日付境界の具体的な時刻（例：0:00）は時間システム側で最終確定する。【未決定】

## 19. ロケット修理と物語・エンディング

### 19.1 星への訪問と修理への協力【採用推奨】

- ゲストが鉱石・資金・加工品を持ち込んで修理を手伝える。
- ロケットはその星の物語上の設備として進行する。
- ゲストの自分の星のロケットまで自動で修理完了しない。
- 星の主人公・管理者が出発のタイミングを決める方向。
- 住民と友達が集まって「最後の引っ越し」を見送る演出を提案する。

### 19.2 共同生活者の立場【未決定】

物語として大きく2案がある。

**案A：訪問者として暮らす**

- 星の主人公のロケットを友達が手伝う。
- エンディングは星の主人公が帰還し、友達は見送る。

**案B：最初から一緒に不時着する**

- 二人以上が同じ宇宙船で漂着し、共同でロケットを修理する。
- 全員が帰還する共同エンディングも成立し得る。

どちらを採用するか、両方可能にするか、ストーリー上の参加者の役割をどうするかは今後決める。**共同居住者を勝手に「主人公ではない」と決めない。**

### 19.3 ロケット修理後

- 帰還後も星へ戻れるか、ワールドを継続できるかはメインストーリー仕様で【未決定】。
- 帰還シーンに他プレイヤーが参加できる場合の条件、ホストや参加者が途中離脱した場合の扱いも【未決定】。

### 19.4 ロケット故障と星間移動の矛盾【追加提案】

- 主人公の故郷は別宇宙にあり、壊れた船を直さないと帰れない。
- 一方、この宇宙の星同士には別の移動手段がある、という設定を提案する。
- この星の住民が引っ越しできる世界観とも整合する。
- ただし、交通手段の形・名前・導入時期・主人公の利用条件は【未決定】。

## 20. EOS P2P・通信方式（設計候補）

### 20.1 推奨構成

**【技術上の有力案・未確定】** EOSのロビー／招待機能とP2P通信を利用し、星の持ち主がホストとして世界を管理する。

```text
           ホスト（星のセーブ正本）
           ├─ 地形・建物・住民AI
           ├─ 農場・生物・商店
           ├─ 日付・天候・鉱山
           └─ クエスト・星での関係履歴
                   │
               P2P 通信
                   │
        ┌──────────┼──────────┐
      ゲストA     ゲストB     ゲストC
      個人辞書    個人辞書    個人辞書
      携帯品      携帯品      携帯品
```

EOS P2Pが世界の進行や保存を自動で実装してくれるという意味ではない。ゲーム側でホスト権限、状態同期、取引確定、セーブ整合性を設計する。

### 20.2 ホストが確定する主な状態【技術推奨】

- 住民の位置・行動・生活イベント。
- 野生生物の行動・捕獲成否。
- 作物の成長・収穫。
- 鉱石の出現・消滅・採掘。
- 商店の購入・売上・委託処理。
- 家具の配置・移動。
- 共通クエストやロケット修理。
- ワールド時刻・天候。

### 20.3 参加時の同期【技術推奨】

1. WorldId、シード、生成規則のバージョン等を確認。
2. 地形・建物など基本世界を準備。
3. 住民、家具、作物、商店、鉱石など**現在のスナップショット**を受信。
4. ゲスト固有の状態を照合。
5. 同期完了後、通常の操作と状態更新へ移行。

**シードだけを送れば現在の世界が復元できるわけではない**。生活の歴史を反映した差分状態も必要。

### 20.4 同時操作と権威

- 同一アイテムの二重取得を避ける。
- 同じ家具を二人が動かした場合の結果を一つにする。
- 農場の収穫と収納移動を一貫して処理する。
- 鉱山の日替わり再生成と採掘処理の順序を決める。
- NPCの位置や会話が参加者間で大きくずれないようにする。

### 20.5 セーブ・切断・再接続

- ホスト終了時、基本案では星のマルチセッションも終了する。
- ゲストが切断した場合、その人の設置物・委託品・預けた生物は星に残る。
- 交換の途中で切断した場合に備え、取引IDと確定状況を持つ。
- 確定済み取引の再送を二重受領として扱わない。
- プレイヤーの携帯品と、星に移した品物の責任境界を明確にする。
- 接続切断からの復帰方法・タイムアウト・保存順序は【要技術詳細設計】。

### 20.6 不正行為と通常の通信事故を区別する

- 通常の切断・再接続でアイテムが消失・重複しにくい構造を目指す。
- 一方で、完全なサーバー権威を持たないP2P＋ローカルセーブでは、意図的なセーブ改変・巻き戻しを完全防止できるとは限らない。
- 本書では、通常のゲーム進行の正しさと、不正対策の範囲を分けて整理する。

### 20.7 専用サーバーについて

- 現時点の設計は、常時稼働する専用ゲームサーバーを前提としない。
- 委託販売・住民生活は、星がホストによって起動されている間に進む。
- 「全星共通の24時間オンライン市場」は本書の採用前提ではない。

## 21. 遊び方のシナリオ例

### 21.1 短期訪問：未知の星を観光

1. 友達の星へ招待される。
2. 自分の星とまったく違う川・住宅・森の配置を見る。
3. 住民が話しかけてくるが、宇宙語は分からない。
4. 友達から辞書を受け取るか、自分で解読するか選ぶ。
5. 珍しい宇宙生物や家具を見つけ、交換する。
6. 自分の星へ戻り、入手した物を飾る。

### 21.2 共同研究：宇宙語を解読

1. Aが商店で商品の値段を変え、購入時の住民の反応を観察する。
2. Bは住民宅で料理中の会話を観察する。
3. マネピの音声カードを持ち寄る。
4. 同じ言葉に別の推測を付け、比較する。
5. 料理や価格を変え、もう一度住民の反応を検証する。
6. 推測は各自の辞書に記録し、正解の自動判定はしない。

### 21.3 共同生活：村に痕跡を残す

1. ゲストが共同居住者になる。
2. 自分の部屋と個人収納を用意する。
3. 農場を二人で発展させる。
4. 友達の生物と自分の生物で料理・加工する。
5. 住民を家に招き、交友関係を深める。
6. 数日後、ゲストが退出する。
7. ホストがソロで遊んでいる間も、設置物や預けた生物が星に残る。
8. 後日再訪し、変わった村と住民に再会する。

### 21.4 星間販売：委託したジュース

1. ゲストが自分の星の果物でジュースを作る。
2. 友達の星へ持参し、商店に委託する。
3. その星の住民が好みに応じて購入する。
4. 商店のマネピに感想の声が預けられる。
5. 次回訪問時に売上を受け取り、宇宙語の手掛かりも集める。

### 21.5 ロケット完成：最後の引っ越し

1. ホストのロケット修理に、友達が資材と資金で協力する。
2. 住民たちが修理の進行を見守る。
3. 星の主人公が帰還を決める。
4. 住民と友達が見送りに集まる。
5. 出発する主人公にとって、友達との生活も一つの思い出になる。

※共同不時着・共同帰還エンディングは別案として未決定。

### 最終的な設計思想

**友達の星には、自分の星とは違う言葉・地形・住民・気候・暮らしがある。**

そこで釣りをし、農業を手伝い、宇宙生物を使って料理を作り、友達と宇宙語の意味を考える。自分が持ってきた家具や料理は、星の住民に使われるかもしれない。自分が去ってからも、そこに暮らす宇宙人たちの生活は続く。

マルチプレイの価値は、単に作業を二人で早く終わらせることではない。**一つの星の生活や歴史に、別の星から訪れた友達の行動も刻まれること**を、本作の中心に据える。
