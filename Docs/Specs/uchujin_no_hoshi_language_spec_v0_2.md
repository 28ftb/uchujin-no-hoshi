## 0. 要約

『宇宙人の星』は、未知の星に不時着した主人公が、かわいい宇宙人たちと暮らしながら、**意味の分からない言語の語彙・文法を、観察と推理によって理解していく生活シミュレーションゲーム**である。

- **【決定】** 最初は住民の話す言葉が分からない。
- **【決定】** 単語の発音・綴りに加え、**語順や文法も星のシードによって変わる**。
- **【決定】** プレイヤーが自分で単語・文法の意味を書き留める。誤った仮説も本人の記録として残る。
- **【決定】** 辞書をほかのプレイヤーに渡すかどうかは任意。訪問者への**自動配布はしない**。
- **【方向性】** 同じ星では一貫した宇宙語を使い、種族ごとにまったく別の言語へ分裂させない。
- **【方向性】** 住民の表情、行動、商店の購入・付箋、住民クエスト、釣り・農業・採掘などの生活を手掛かりにする。
- **【方向性】** 宇宙語を完全に解読できなくても生活・金策・宇宙船の修理・帰還を進められる。
- **【提案】** 意味データを星固有の言語規則で宇宙語へ変換する仕組みと、会話の証拠を辞書・住民辞典・生き物図鑑・依頼帳へ関連付ける仕組みを採用する。

**目標体験**：*「昨日まで読めなかった言葉が、同じ表示のまま今日になって理解できる」*。言語レベルアップによる自動翻訳ではなく、プレイヤー自身の理解を成長させる。

## 1. 本作のゲーム性との関係

### 1.1 言語解読だけのゲームにはしない【決定・方向性】

本作には、釣り、鉱山・採掘、農業、野生生物の捕獲・飼育、商店経営、クエストなどの生活コンテンツがある。これらは**言葉を知らなくてもそれぞれ遊べること**を基本とする。

宇宙語を理解すると、住民の希望、商品評価、釣り・採掘・飼育の助言、個別ストーリーなどをより深く理解できる。言語を解読するために生活を強制するのでも、生活するために一定の解読率を強制するのでもない。

### 1.2 主人公の言葉を相手に教えるゲームではない【方向性】

主人公は基本的に普通のセリフを話さず、**うなずく・首を振る・指さす・物を渡す・行動する**などで意思を示す。住民たちは最後まで原則としてその星の宇宙語を使用する。

「住民が主人公の日本語／英語を習得する」という別系統の言語学習は主軸にしない。エンディングでも宇宙語を自動的に母語へ切り替えない。

### 1.3 生活と同時進行する解読【方向性】

宇宙語は専用の問題集ではなく、住民の日々の言動に現れる。同じ言葉を複数の場所で聞き、プレイヤーが状況を比較して推理する。

| 活動 | 手掛かりとなる出来事 | 推測できる言葉の例 |
|---|---|---|
| 商店 | 購入・買い控え・値下げ・顔付き付箋 | 高い、安い、好き、欲しい、珍しい |
| 釣り | 魚を指す・釣果への反応・名人の実演 | 魚、大きい、釣る、逃げる |
| 鉱山 | 鍛冶屋が材料を示す・岩が掘れない | 硬い、壊す、深い、石 |
| 農業 | 種まき・水やり・収穫・住民の庭 | 水、育つ、大きい、おいしい |
| 生き物取り | 生物の行動・住民による観察 | 飛ぶ、眠る、速い、かわいい |
| クエスト | 依頼文・絵・身振り・納品結果 | 持ってくる、渡す、明日、数量 |
| 村の日常 | 挨拶・仕事・友人関係・引っ越し | 今日、友達、行く、帰る、ありがとう |

> 上記の日本語は仕様説明用の内部的な意味であり、ゲーム中の宇宙人の発言をそのまま翻訳表示するものではない。

## 2. 宇宙語の基本原則

| 項目 | 方針 | 状態 |
|---|---|---|
| 星と言語の関係 | 一つの星に一つの共通言語を基本とする | 【方向性】 |
| 語彙 | 星のシードで変化 | 【決定】 |
| 語順・文法 | 星のシードで変化 | 【決定】 |
| 同じ星の一貫性 | 同じ意味・同じ構文ルールを再利用 | 【方向性】 |
| 住民の個性 | 主に話題、発言頻度、文量などで表現 | 【提案】 |
| 会話・付箋・掲示板 | いずれも同一の星固有言語を使用 | 【方向性】 |
| プレイヤー辞書 | 自分で作成・自由修正 | 【決定】 |
| 誤訳の扱い | 勝手に正解へ修正しない | 【決定・方向性】 |
| 習得条件 | 暗記率・言語スキル上昇による正解解放を基本にしない | 【方向性】 |
| クリア条件 | 全語彙や文法の理解は不要 | 【方向性】 |
| 宇宙文字・音声 | 表示方式と音声表現の採否は未確定 | 【未決定】 |

### 2.1 世界の側の言語は最初から完成している【方向性】

ゲーム序盤だから住民が簡単な文しか使わない、後半に否定や過去形がアンロックされる、といった構成を基本にしない。**住民たちは最初から自分たちの言語で普通に話す**。最初に理解できないのは主人公・プレイヤーの側である。

### 2.2 ランダムでも言語として破綻させない【決定・方向性】

- 無意味な文字列の寄せ集めや、日本語の語を置換するだけの暗号にしない。
- 同じ星では、用いられる語彙と文法規則を基本的に固定する。
- 主語・目的語・受け手など、重要な意味の違いを文章で表現できることを重視する。
- 文法がランダムだからといって、推理を妨げる不規則な例外だらけにしない。
- 同じ宇宙語が別の状況に再登場し、プレイヤーが仮説を試せるようにする。

## 3. 星のシードで変化する言語

### 3.1 基本構造【提案】

1. 星のシードから、言語生成に使う情報を決定する。
2. 語彙・語順・文法・発音に関するルールを決定する。
3. 会話の「意味」を、この言語ルールに従って宇宙語の文へ変換する。
4. 会話、付箋、看板、依頼文などに、同じルールから生成した文章を表示する。
5. プレイヤーは行動・表情・対象物・繰り返しを手掛かりに意味を推測する。

### 3.2 語順【決定：変動対象／詳細は提案】

- 主語（S）・動詞（V）・目的語（O）の基本順序を星ごとに変える。
- 形容詞と名詞の順序も、星ごとの規則として変化させる候補。
- 文法上の格を語順で示す言語と、付属語などで示す言語を作る候補。

### 3.3 文法の変動候補

| 要素 | 星による違いの例 | 状態 |
|---|---|---|
| 主語・動詞・目的語 | SOV、SVO、VSOなど | 【決定：変動方針】 |
| 形容詞の位置 | 「赤い 魚」／「魚 赤い」 | 【提案】 |
| 否定 | 動詞の前後に否定語／語幹に接辞を付加 | 【方向性】 |
| 疑問 | 疑問語の位置、文構造の変化 | 【方向性】 |
| 時間 | 時制語、動詞の変化、時間表現 | 【方向性】 |
| 希望・依頼 | 欲しい／してほしいを区別して表現 | 【方向性】 |
| 所有 | 所有者と対象の順序、専用の付属語 | 【方向性】 |
| 格（誰が・何を・誰に） | 語順または標識の使用 | 【方向性】 |
| 数・複数 | 単複区別や数量の表し方 | 【提案・未決定】 |
| 発音規則 | 音節、単語長、使う音の偏り | 【提案】 |

### 3.4 原則として採用しないもの【決定】

- 日本語の「ね」「よ」「な」など、意味の解読にほぼ寄与しない細かな終助詞の再現。
- 英語の `a` / `the` のような冠詞の基本仕様への組み込み。
- 文法上の性別による名詞・形容詞などの変化。

**注意**：すべての付属語をなくす方針ではない。**否定、疑問、格、時制、希望、所有**など、文の意味を変えるものは必要に応じて残す。

### 3.5 同じ意味でも星ごとに文章が違う例【説明用】

内部的な意味：**「私は赤い魚が欲しい」**。

| | 宇宙語の例 | 便宜上の構造 |
|---|---|---|
| 星A | `Mii sela roku ke pari` | 私／赤い／魚／目的語標識／欲しい |
| 星B | `Vema ona tuki nala` | 欲しい／私／魚／赤い |

否定形「私は赤い魚が欲しくない」にすると、星Aでは動詞前に否定語 `nu` を置いて `Mii sela roku ke nu pari`、星Bでは動詞に接辞を付けて `Vemasa ona tuki nala` とする、といった違いが作れる。

> 上記は**生成結果の説明用サンプル**。確定した辞書、スペル、語形変化ではない。ゲーム内で構造の日本語解説は表示しない。

### 3.6 音のまとまり【提案】

星ごとに、使いやすい音の組み合わせや音節長の傾向を持たせる。短い単語が多い星、濁音が多めの星など、**同じ星の言葉として聞こえる統一感**を作る。

ただし、音の多様性だけを追求して、区別しにくい単語だらけにしない。単語の衝突や発音上の判別困難さは検証対象とする。

## 4. 語彙設計

### 4.1 生活で必要な意味から語彙を作る【提案】

先に固定語数を決めるのではなく、釣り・鉱山・農業・生き物取り・商店・住民イベント・メインストーリーで必要な発話内容を整理する。

| 分類 | 意味の例 |
|---|---|
| 人・関係 | 私、あなた、友達、家族 |
| 動作 | 行く、来る、渡す、買う、売る、食べる、釣る、育てる |
| 感情・評価 | 好き、嫌い、嬉しい、怖い、高い、安い、おいしい |
| 状態・性質 | 大きい、小さい、硬い、珍しい、きれい、壊れた |
| 時間 | 今日、明日、昨日、朝、夜 |
| 数量 | 数字、多い、少ない、全部 |
| 場所・方向 | 上、下、中、外、近く、遠い |
| 生活 | 家、店、魚、作物、道具、鉱石、水 |
| 文法的意味 | 否定、疑問、時制、依頼、希望、所有、格 |
| 固有名詞 | 住民名、地名、魚種、宇宙生物50種類、作物、鉱石など |

以前の「基礎語彙100〜200語」は**検討用の一例**。最終的に300語や500語が必要なら増やす。プレイヤーに全語彙の暗記を必須としない。

### 4.2 意味の区別と多義語【提案】

日本語の「高い」は、価格と高さで意味が違う。内部データ上では、例えば以下のように区別して扱う候補。

- `PRICE_EXPENSIVE`：値段が高い
- `HEIGHT_TALL`：背や高さが高い
- `SIZE_LARGE`：大きい
- `PRICE_CHEAP`：値段が安い
- `QUALITY_GOOD`：品質がよい

星ごとの言語で意味が統合される多義語を許すか、同音異義語をどの程度許すかは未決定。少なくとも、**ランダム生成による偶然の衝突と、意図した多義性は分けて扱う**。

### 4.3 固有名詞【提案】

アイテム名、住民名、生物名などは、生活で使う基本語彙と区別して扱う候補。特に住民の名前はプレイヤーが最初から正しく把握しているとは限らない。

星のシードによってどこまで固有名詞を変えるか、星をまたぐ同種生物の呼び名をどう対応させるかは未決定。

## 5. 会話の意味と住民の生活を一致させる

### 5.1 住民は最初から普通に会話する【方向性】

住民が日常で交わす話題：挨拶、買い物、仕事、友人関係、食べ物、予定、過去の思い出、将来の夢、引っ越しなど。

会話の長さ・話題の傾向は住民によって違ってよい。例えば、おしゃべりな住民は長めの説明をし、無口な住民は短い発言が多い。**同じ星では基本的に共通の語彙と文法を使用**する。

### 5.2 発言内容は現実の状況に結びつける【提案】

| 内部的な発言の意味 | 生活の中で観察できる手掛かり |
|---|---|
| 魚が欲しい | 魚売り場を見る、購入する、探しに行く |
| お腹がすいた | 食事を探す、食べる |
| この商品は高い | 値段を見て迷う、買い控える場合がある |
| 明日は休み | 翌日の仕事予定が変わっている |
| あの住民に会いたい | 会いに行く、話しかける |
| 引っ越しを考えている | 住居や荷物、ほかの住民との会話に兆候がある |

未来の予定が変更になること自体はあり得る。重要なのは、**発言した時点で、その住民の状態・意図・認識と矛盾しない意味が生成されること**である。

### 5.3 固定イベントと生活会話を両立【提案】

- 住民固有のストーリー：意味のある会話内容と出来事を設計する。
- 日常会話：住民の仕事、性格、気分、予定、近くの対象物などに基づいて生成・選択する。
- 商店の付箋：購入者の実際の評価に基づいて文章を作る。
- クエスト：依頼対象、必要数、理由、期限などの意味情報と文章を対応させる。
- 看板：表示対象の場所や施設に対応する意味を持たせる。

いずれも**会話の意味はゲーム内の事情と整合**させ、その後に宇宙語へ変換する。

## 6. 解読の基本体験

### 6.1 推理できる手掛かりを複数用意する【方向性】

1. **観察**：住民の身振り、表情、行動、商品、魚、生物などを見る。
2. **比較**：似た状況で聞いた文章の共通部分・異なる部分を調べる。
3. **仮説**：単語や文法の意味を自分で考える。
4. **記録**：辞書や辞典へ書き込む。
5. **検証**：別の場面で同じ語・表現を聞き、予想と一致するか確かめる。
6. **修正**：誤解に気づいたら、自分の判断で辞書を編集する。

### 6.2 同じ文章を比較して文法を推理する【説明例】

| 宇宙語（仮） | 住民の行動から推測できる状況 |
|---|---|
| `Mina pol tema` | 魚を欲しがる |
| `Mina bat tema` | 果物を欲しがる |
| `Mina pol ne tema` | 魚を差し出されて断る |

プレイヤーは `pol` が魚、`bat` が果物、`tema` が欲しい、`ne` が否定に関わるのではないかと推測できる。ただし、これらの訳を**ゲームが正解として表示しない**。

### 6.3 「状況」「比較」「長い会話」を共存させる【提案】

- **状況から意味を想像しやすい発言**：商品を見て「高い！」と言うなど。
- **複数の文章を比較すると規則が見える発言**：「欲しい」「欲しくない」など。
- **語彙・文法の理解が進むと読める発言**：過去の思い出、夢、人間関係など。

難しい会話は最初から存在してよい。進行に合わせて言語そのものが変わるわけではない。

### 6.4 プレイヤーが自分で実験できる【提案】

- 同じ商品の価格を変更し、住民の買い方や付箋を比較する。
- 店の棚の商品を入れ替え、会話中で変化する語を調べる。
- 住民が好きな品物と嫌いな品物を示したときの発言を比較する。
- 翌日の住民の行動から「明日」「行く」「仕事」などの語を推理する。
- 魚・野菜・宝石など異なる対象について、共通して使われる「大きい」「珍しい」などを探す。

**注意**：住民には個性や主観がある。「ある人が高いと思う価格」は、ほかの人にとって高いとは限らない。主観の違いを、言葉の意味のランダムな変更と混同しない。

## 7. 宇宙語辞書

### 7.1 辞書の役割【決定】

宇宙語辞書は、システムが作る正解集ではなく、**プレイヤー自身が作る研究ノート**とする。

- 単語・表現・文法の意味を自由入力する。
- まだ不明な語や、自信のない仮説を記録する。
- 間違いだと気づいたら、自分で修正する。
- 自分のメモをゲームが自動的に正解へ置き換えない。

### 7.2 保存項目【提案】

| 項目 | 内容 |
|---|---|
| 原文 | 宇宙語の単語・文・気になる語尾など |
| 推測訳 | プレイヤーによる自由記述 |
| 文法メモ | 語順、否定、時制、格などの仮説 |
| 出典 | どの会話・付箋・看板・依頼で見たか |
| 自由メモ | 当時の状況、自分の考え、注意点 |
| 自信の印 | 仮説、たぶん正しい、自信あり等の任意マーク |
| 関連資料 | ほかの単語や記録への参照 |

### 7.3 記録の操作性【提案】

- 会話や付箋の文字列を選択し、そのまま辞書へコピー・登録できる。
- 文全体を保存するほか、単語単位、必要なら接辞に相当しそうな一部分にもメモできる。
- 原文・推測訳・自由メモから検索できる。
- 例文や証拠となる付箋を後から見直せる。
- 単語を何度も手動で書き写す負担を減らす。ただし、**意味を決める作業はプレイヤー本人**が行う。

### 7.4 推測訳の会話表示【提案】

プレイヤーが `Mii＝私`、`roku＝魚`、`pari＝欲しい` などと入力していた場合、宇宙語の原文の下に**自分の推測訳**を併記する機能を候補とする。

- 表示／非表示を切り替え可能にする。
- プレイヤー自身の推測だと分かる見た目にする。
- 間違った訳を書いていれば、間違ったまま表示する。
- **原文を必ず参照できる**ようにする。
- 接辞や語順が複雑な場合の併記・置換ルールは未決定。

辞書に「高い」と書いたことによって、ゲームが解読成功を認定して正解を教える仕組みにはしない。

## 8. 会話・付箋・辞典・依頼帳との連携

### 8.1 共通の証拠資料【提案】

証拠として保存できるものの例：

- 住民が話した宇宙語の原文
- 発言した住民（顔・内部ID）
- 見聞きした日時と場所
- 商店の商品、当時の価格、購入の有無
- 住民が実際に示した絵や現物
- クエストの原文と進行中に見た出来事
- 看板、手紙、住民が書いた付箋

**確実に見聞きした事実**と、**プレイヤーが推測した意味**を区別して保存する。ゲームが見せていない目的・感情・正解を勝手に補足しない。

### 8.2 4種類のノート【提案＋既存方針との連携】

| 記録先 | 主な役割 | 内容 |
|---|---|---|
| 宇宙語辞書 | 言葉と文法を知る | 語彙、例文、推測訳、文法仮説 |
| 住民辞典 | 住民を知る | 仮の呼び名、性格、好み、行動、関係性 |
| 生き物図鑑 | 宇宙生物を知る | 出現場所、習性、捕獲方法、自由メモ |
| 依頼帳 | 依頼を振り返る | 宇宙語原文、示された物、進捗、自分の推測 |

同じ資料を複数のノートに関連付けられるようにする候補。例えば、商店で「モギラ！」という顔付き付箋を見つけた場合、宇宙語辞書には「高い？」の証拠として、住民辞典には「この住民は値段に敏感かも」の根拠として保存できる。

### 8.3 商店の顔付き付箋【既存の方向性との連携】

商店は、商品を陳列しておけば住民が自分で購入し、売上が自動発生する方式を採用する。**カウンターで常時注文を聞く方式は基本にしない**。

住民は商品の価格、品質、珍しさ、好き嫌い、要望などについて、**顔付きの付箋**を残すことがある。

- 内容はその星の宇宙語。
- 付箋には書いた住民が分かる顔を付ける。
- 商品名・当時の価格・購入／非購入といった観察情報を残す候補。
- 値下げや品替えによって住民の反応が変わり、語の意味を検証できる。
- 付箋は宇宙語辞書と住民辞典へ保存・関連付けできる候補。

### 8.4 依頼帳【クエスト案との連携】

- 依頼の原文を宇宙語で保存する。
- 住民が**実際に**見せた絵や物だけを記録する。
- システムが「魚3匹必要」などと、原文から答えを自動抽出して表示することを基本にしない。
- 進行中／完了などの操作用情報は通常のUI言語で確認できる。
- 後から宇宙語を覚えて、過去の依頼を読み返せる。

### 8.5 住民の名前【提案】

初対面では住民の名前も不明とし、顔と内部IDだけで管理する候補。プレイヤーは住民辞典に「釣りのおじいちゃん」など自由な呼び名を付けられる。住民同士の呼びかけから本名を推理したら、自分で書き直せる。

システムの人物判定は、プレイヤーが書いた仮名や誤ったメモではなく内部IDで管理する。

## 9. 生活コンテンツでの具体的な解読例

### 9.1 商店：値段の言葉

1. 星リンゴを高い値段で並べる。
2. 住民が購入せず「モギラ！」という付箋を残す。
3. 値下げして同じ住民の反応を観察する。
4. 別の住民も別の商品で同じ語を使っていることに気づく。
5. 「モギラ＝高い？」と辞書に記録する。

これは**推測の例**。ゲーム側が日本語の正解を表示するものではない。

### 9.2 釣り：大きさの言葉

巨大魚を釣ったときに聞いた語が、後日巨大な作物を見た住民の会話にも出てくる。魚名ではなく「大きい」に関する語かもしれないと推理する。

### 9.3 鉱山：硬さと強化

鍛冶屋が硬い鉱石を示し、ツルハシの素材を指さす。絵や現物によって強化の手順は理解できるが、会話の語彙を理解すれば「硬い」「強い」「作る」などの意味にも気づける。

### 9.4 農業：水と成長

農業用のミズプクが水をまいた際の住民の言葉が、雨の日にも聞こえる。別の農場では作物の成長について同じ文法表現が使われる。

### 9.5 生き物取り：習性

住民が飛んでいる生物を見て言った語が、別の場所で空を飛ぶ生物の説明にも登場する。住民の観察・生き物図鑑・辞書を行き来して推理する。

### 9.6 クエスト：数と依頼

住民が魚の絵を見せながら指を3本立てる。別の依頼で花の絵を見せながら指を2本立てる。依頼文中で変わる語・変わらない語を比べ、対象物や「持ってきて」の表現を調べる。

## 10. 誤解と気づきによる物語

### 10.1 誤訳を許す【決定・方向性】

「嫌い」だと思っていた語が、別の場面を見て「怖い」だと分かる、といった再解釈を楽しめるようにする。ゲームは誤訳を自動修正しない。保存した過去の会話を読み返す意味が生まれる。

### 10.2 住民の人格・物語を理解する【方向性】

住民の夢、過去の思い出、友人関係、引っ越しの理由などは、単純な身振りだけでは完全に伝わらない場合がある。語彙と文法を覚えることで、**以前から見ていた行動の理由**に気づける。

### 10.3 帰還時も宇宙語のまま【方向性】

メインストーリーの最終章「最後の引っ越し」でも、住民は基本的に宇宙語で主人公を見送る。理解できる範囲はプレイヤーによって異なる。特別な翻訳演出によって一律に正解を表示せず、これまでの辞書や記憶が最後に生きる構成を目指す。

## 11. 文字・発音・音声

### 11.1 表記方式【未決定】

候補は、①アルファベットなど読み写しやすい表記、②オリジナルの宇宙文字、③宇宙文字と発音表記の併用。

宇宙語を見分けたり辞書に記録したりすることが本作の中心なので、**文字を読み分けられること、必要な文字列を選択・保存できること**を重視する。

宇宙文字の形そのものをシードごとに変えるか、文字解読まで別の謎解きにするかは未決定。

### 11.2 発音・声【提案・未決定】

- 星の発音規則と、住民ごとの声質・話し方を区別する。
- 丸い住民の高い声、大きな住民の低い声などの演出候補。
- 音声を正確な単語の手掛かりにするか、意味のない会話効果音中心にするかは未決定。
- 表示された綴りと発話の対応を崩して、解読できなくなる設計は避ける。

## 12. マルチプレイと言語・辞書

### 12.1 訪問先の言語【決定・方向性】

- ホストが開いた星では、その星の宇宙語を表示する。
- ゲストが別の星の語彙や文法を覚えていても、その知識は原則としてそのまま通用しない。
- 同じ星を再訪する場合は、以前の辞書を参照できるようにする候補。

### 12.2 辞書の任意受け渡し【決定】

- 訪問時に辞書を自動配布しない。
- ホストが訪問者に辞書を渡しても渡さなくてもよい。
- プレイヤーが自分で書いた仮説や誤訳も辞書の内容として扱う。
- 相手に辞書を渡しても自分の記録が失われないコピー方式、一部のページだけ共有する方式などは追加提案で、詳細未決定。

### 12.3 辞書の管理単位【提案】

自分の星A、友達の星B、別の友達の星Cについて、それぞれ辞書を保存する。星を再訪した際に対応する辞書を再び使えるようにする。世界ID・ホストID・言語IDなどの具体的な識別方法は未決定。

### 12.4 受け渡しと誤情報【提案】

プレイヤーが意図的に間違った情報を書いた辞書を渡す遊びも想定できる。ゲームは共有された辞書を「公式の正解」として扱わない。別言語のプレイヤーへの自由メモの受け渡し方法はローカライズ項目で別途検討する。

## 13. 多言語ローカライズ

### 13.1 基本方針【方向性】

**同じ星なら、日本語版・英語版などで同じ宇宙語が表示される**方式を有力案とする。

| 表示対象 | 表示言語の方針 |
|---|---|
| 設定・操作説明 | プレイヤーの選択言語 |
| アイテム管理・価格などの通常UI | プレイヤーの選択言語 |
| 宇宙人の会話 | 星固有の宇宙語 |
| 宇宙人の付箋・手紙・看板 | 星固有の宇宙語 |
| 宇宙語辞書の自由メモ | 入力した本人の言葉のまま |
| 住民辞典・生き物図鑑の自由メモ | 入力した本人の言葉のまま |

### 13.2 ローカライズで守ること【決定・方向性】

- 日本語独自の「ね」「よ」のような終助詞を謎解きの必須要素にしない。
- 英語の冠詞や文法性に依存した問題を基本にしない。
- 宇宙語は特定の国の文章を直接変換するのではなく、**言語非依存の意味データ**を元に生成する候補。
- プレイヤーの入力したメモを、システムによる正しい翻訳だと混同しない。
- 異なる言語圏のプレイヤー間で辞書を共有する際の、自由メモの表示や任意翻訳の扱いは未決定。

### 13.3 問題のない手掛かりを作る【提案】

「高い値札に驚く」「大きな魚に反応する」「水をまく」など、言語圏を問わず状況が伝わりやすい手掛かりを優先する。言語ごとの文化差・認知差を検証し、特定の国の文法知識がある人だけ有利になる設計を避ける。

## 14. 実装アーキテクチャの有力案

> **この章は技術設計上の提案であり、採用済みの内部データ形式ではない。**

### 14.1 意味と表面の文章を分離【提案】

1. **世界状態**：住民の好み、予定、購入・売却の結果、依頼、友好関係など。
2. **発言の意味**：誰が、何を、誰に、いつ、どうしてほしいのか等。
3. **星の言語定義**：語彙・語順・文法・発音・生成バージョン。
4. **表面形生成**：意味データを星固有の宇宙語へ変換。
5. **出典つき記録**：宇宙語原文、住民、場所、時刻、対象物など。
6. **プレイヤーノート**：自由メモ・推測訳・証拠リンク（正解情報とは別管理）。

### 14.2 データ構造の概念例【技術メモ・未確定】

```text
意味データ：
  発話者 = 住民A
  発話行為 = 希望の表明
  対象 = 青い魚
  数量 = 3
  理由 = 料理に使いたい

言語定義：
  星ID = 星A
  語彙対応 = 星Aの固有辞書
  語順・格・否定・時制など = 星Aの固有ルール

生成結果：
  星Aの宇宙語による発言

プレイヤーノート：
  上記発言の原文と、自分が推測した意味
```

**重要**：この例は説明用の構造であり、データキーや実装クラスを確定しない。

### 14.3 シードの再現性とセーブ【提案】

- 同じ星の言語はセーブ・ロード後も変化しない。
- マルチのホストとゲストで同じ宇宙語の文章になる。
- アップデートで生成アルゴリズムが変わっても既存の星の言葉が突然変化しないよう、言語の定義や生成バージョンを保存する案。
- 付箋や古い会話の原文が、後から勝手に別の宇宙語にならないようにする。
- プレイヤーの自由メモとゲーム内部の意味データは独立して保管する。

### 14.4 翻訳エンジンではなく意味から生成【提案】

日本語版の文章を宇宙語へ単語置換し、その結果を各言語へ変換する方式は避ける。意味データを先に設計し、星ごとの文法に基づいて表面の文章を作る。多言語版のUIは別系統としてローカライズする。

### 15.4 マルチ・ローカライズ

- [ ] 星別の辞書記録を取り違えない。
- [ ] 日本語版・英語版などで同じ星の宇宙語が一致する。
- [ ] プレイヤーの自由入力メモが、正答翻訳として扱われない。

### 15.5 ストーリー・クリア

- [ ] 言語解読率にかかわらず、金策・宇宙船修理・帰還へ到達できる。
- [ ] エンディングの別れの会話も、従来と同じ宇宙語・文法で表現できる。
- [ ] 言語を多く覚えた人ほど、会話の意味や住民との関係を深く受け取れる。

## 17. 既存仕様との整合・採用しない設計

### 17.1 避けること【決定・方向性】

- 単語を日本語から架空の文字列に置換するだけで終わらせない。
- 文章が無意味なランダム文字列にならないようにする。
- プレイヤーの辞書をシステムが自動的に正解へ修正しない。
- 宇宙語レベルを上げたら正解訳が自動開放されることを本作の中心にしない。
- 訪問プレイヤーへ辞書を自動配布しない。
- 主人公が日本語・英語などで普通に話し、住民がそれを学ぶ仕組みを主軸にしない。
- 宇宙語を完璧に理解しなければロケット修理できない設計にしない。
- 日本語独自の「ね」「よ」や英語の冠詞を解読の必須文法にしない。
- **すべてのクエストで、依頼文の正解を日本語で自動表示しない。**

### 17.2 他の企画との接続【既存仕様との連携】

- **商店**：セルフ販売方式。住民の顔付き付箋が言語解読の重要な証拠になる。
- **住民辞典**：性格・好み・名前・人間関係についてプレイヤーが自由記入する。
- **クエスト**：依頼は宇宙語を基本とし、行動・身振り・実物などから推理できる。
- **農業**：農作業を手伝う宇宙生物、住民の畑、作物販売などの場面で同じ語が使われる。
- **生き物取り**：約50種類の宇宙生物を想定。名前・行動・習性を住民の発言と結びつける。
- **釣り・鉱山**：名人や鍛冶屋との交流に言語解読が自然に登場する。
- **村の季節**：**四季は設けない方向**。時間帯・天候・住民の生活・イベントから会話を生み出す。
- **メインストーリー**：宇宙船を修理して故郷へ帰る。言語解読の進度で別れの理解が変わる。

## 19. この仕様書の結論

本作の宇宙語は、単に読めない台詞を並べる演出ではない。**住民の行動、生活の結果、商店の価格、釣果、農作物、採掘、生物の習性などと、同じ言葉が何度も結びつくこと**によって解読できるものとする。

プレイヤーが作る辞書は、正答一覧ではなく仮説と証拠の蓄積である。誤解したまま暮らすことも、何度も検証することも、誰かに辞書を渡さないことも選べる。

**ゲーム側の世界と言語は初日から存在している。変化していくのは、プレイヤー自身がその世界を理解する深さである。**

この体験を、『宇宙人の星』の宇宙語・言語解読システムの中心に据える。
