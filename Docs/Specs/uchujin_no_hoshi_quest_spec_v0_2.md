# 宇宙人の星 — クエスト・住民イベントシステム仕様案 v0.2

- **作成日**：2026年10月15日
- **対象作品**：『宇宙人の星』（仮題）
- **ステータス**：企画・詳細検討用。**実装の最終確定仕様ではない**
- **位置付け**：これまでのクエストに関する会話（v0.1 → v0.2）を統合し、他の生活システムとの接続を整理したもの。
- **関連資料**：企画・暫定仕様書 v0.1／メインストーリー案 v0.2／商店詳細仕様案 v0.2／魚釣り仕様案 v0.2／鉱山仕様案 v0.4／農業・農場仕様案 v0.2／生き物取り・宇宙生物仕様案 v0.2／住民デザイン案 v0.1

> **クエストの中心思想：クエストをクリアするために住民と話すのではなく、住民と暮らしていたら自然とクエストが生まれる。**
>
> 言葉が通じない状態でも手探りで行動できる。宇宙語が少しずつ分かると、同じ出来事の背景や住民の気持ちが理解できる。クエストの成果は村の日常に戻り、思い出として辞典に残る。

## 0. 記載区分と変えてはいけない前提

### 0.1 記載区分

- **【既存決定】**：ほかの企画・仕様で明確に決定・除外された内容。
- **【採用方向】**：これまでの議論で目指している方針。ただし詳細は未確定。
- **【提案】**：今回までに考えたアイデア。採用確定とは扱わない。
- **【未決定】**：今後調整・検討する要素。

**重要：提案を無断で決定事項に昇格させない。制作を楽にするために内容や住民の物語を勝手に削らず、面白さを起点に検討する。**

### 0.2 企画全体から引き継ぐ前提

1. 【既存決定】主人公は別宇宙から来て、未知の星に不時着する。お金を稼ぎ、修理部品を買い、宇宙船を直して故郷へ帰る。
2. 【既存決定】住民の言葉は最初分からない。**語彙だけでなく語順・文法も星のシードで変わる**。
3. 【既存決定】プレイヤーは言葉の意味を自分で推測し、辞書に記録する。**ゲームは勝手に正解訳を書き込まない**。
4. 【既存方向性】主人公は基本的に通常の日本語・英語などのセリフを話さない。行動や身振りで意思を示す。住民は最後まで宇宙語を話す。
5. 【既存決定】宇宙語の完全解読はロケット修理・帰還の必須条件ではない。
6. 【採用方向】住民は多様でかわいい宇宙人。個々に生活・性格・関係性があり、引っ越しによる入れ替わりがある。
7. 【既存決定】商店は陳列した商品を住民が自分で買う自動販売方式。クエストのためにレジでの常時接客を強制しない。
8. 【採用方向】**四季は設けない予定**。季節限定クエストを基本条件にはしない。
9. 【既存決定】マルチプレイで辞書を自動配布しない。渡すかどうかは持ち主が決める。
10. 【既存方向性】釣り・鉱山・農業・生き物取り・商店・住民交流は、それぞれ普通に遊んでも面白い生活コンテンツとする。

## 1. クエストの役割

### 1.1 目指す体験【採用方向】

- **暮らしから生まれる**：住民が仕事や日常で必要になったものを頼む。依頼のためだけに住民が存在するわけではない。
- **言語解読の手掛かりになる**：会話、身振り、絵、実物、前後の出来事を見て意味を推測する。
- **プレイヤーの行動が反映される**：依頼をどう解決したかで住民の反応や暮らしに変化が残る。
- **生活コンテンツをつなぐ**：釣り・採掘・農業・生き物取り・商店などを好きな方法で利用できる。
- **住民への理解が深まる**：最初は理由を知らずに手伝い、後から事情や感情が分かることもある。

### 1.2 避けたい設計【既存方針／提案】

- 依頼を受けるたびに、宇宙語が日本語の正解説明へ自動変換される。
- 謎解きのためだけに、生態や行動と噛み合わない手掛かりをばらまく。
- 全依頼に「正解の品物アイコン・数量・目的地」を無条件に表示する。
- 逆に、何の手掛かりもなく宇宙語を総当たりで当てないと進めない。
- 住民が主人公の依頼待ちで何日も棒立ちし、暮らしが止まる。
- 不正解を一度選んだだけで、住民の物語が理不尽に永久消滅する。
- 釣りや商売だけを楽しみたい人に、大量の住民クエストをメイン進行の必須条件として押し付ける。

## 2. クエストは5系統【採用方向】

| 系統 | 内容 | 主な楽しさ | 想定される進行 |
|---|---|---|---|
| **① 日常のお願い** | 納品・配達・採集・買い物など | 金策、生活サイクル | 繰り返し発生する依頼が中心 |
| **② 住民の個別ストーリー** | 性格・夢・悩み・友人関係など | 人物理解、感情移入 | 複数の出来事が連続する場合がある |
| **③ 自発的なお手伝い** | 住民の困りごとを見て自分から行動 | 観察、気付き、即興 | 正式な受注がなくても開始できる |
| **④ 村のイベント** | 誕生日・祭り・引っ越し・共同作業 | 村で暮らす実感 | 時間・人間関係・村の状況に連動 |
| **⑤ メインストーリー** | 宇宙船の調査・部品購入・修理・帰還 | 明確な長期目標 | プレイヤーのペースで進める |

各系統は排他的ではない。例えば「住民の個別ストーリー」の途中で「日常のお願い」が発生し、「村のイベント」へつながってもよい。

## 3. 依頼に気付く／関わる入口【提案】

| 入口 | 例 | 直接得られる手掛かり |
|---|---|---|
| **住民から直接** | 住民が話しかけ、何かを頼む | 宇宙語、表情、身振り、実物 |
| **掲示板** | 住民の募集を見つけて引き受ける | 宇宙語の原文、署名、本人が描いた絵 |
| **現場の観察** | 荷物運び、落とし物探しなどに気付く | 実際の行動、周囲の状態 |
| **商店から** | 常連の要望、売り切れ棚への顔付き付箋 | 客の顔、宇宙語の付箋、商品や価格の状況 |
| **ほかの住民から** | 友人や家族の困りごとについて耳にする | 会話・他者の反応・人間関係 |
| **過去の出来事から** | 以前手伝った住民が新しい相談を持ってくる | 以前の依頼・記憶・住民辞典 |

**正式な受注を全クエストの必須条件にしない。** 住民の行動を見て手伝ったことで、あとから「手伝いをした出来事」として記録される形も認める。

## 4. 宇宙語が分からない状態でも成り立つ依頼【既存方針／提案】

### 4.1 依頼の理解には3つの段階を用意

| タイプ | 状況 | 体験例 |
|---|---|---|
| **A：見れば分かる** | 行動・現物・現場の状態でほぼ理解できる | 荷物を運ぶのに困っている住民を手伝う |
| **B：推理して分かる** | 宇宙語と絵・指差し・数・出来事を組み合わせる | 住民が何匹かの魚を欲しがっていると推測する |
| **C：言葉が分かるほど事情が深まる** | 行動は取れるが、理由や関係性は会話理解で見えてくる | 花の配達が、実は友人への感謝のためだったと知る |

これは難易度の固定ランクではなく、プレイヤーが何を理解できるかを説明する分類。同じ依頼でも言語理解の進み具合により受け取り方は違う。

### 4.2 「手掛かり」は住民が実際に出したものだけ【採用方向】

- 住民が赤い魚の絵を見せたなら、それを依頼帳に残してよい。
- 指を3本立てたなら、その場面や数を記録してよい。
- 何も見せていないのに、UIが答えを示す魚アイコンや「赤い魚×3」を自動で出すのは避ける。
- 原文が不明な単語を含んでいても、既知語と同じものが繰り返し登場することで推理できる。
- 文字が読めなくても、状況や身振りから試せる依頼を用意する。

### 4.3 誤解から起きるやり取り【提案】

**例：花を持った住民のお願い**

1. 住民が青い花を見せながら宇宙語で何かを頼む。
2. プレイヤーは「この花を欲しがっている」と推測して渡す。
3. 住民は困った顔をし、別の住民の家を指さす。
4. 実際には「この花を友達に届けてほしい」というお願いだった。
5. プレイヤーは身振りから気付き、配達する。後に宇宙語を覚えると意味を理解できる。

誤解は本作の魅力の一つ。単純な「不正解・失敗」表示だけで処理せず、住民のリアクションや再説明がゲーム体験となるようにする。

## 5. 依頼の受け答え・達成判定【提案】

### 5.1 主人公の意思表示

- 引き受ける：うなずく、荷物を預かる、実際に手伝い始める。
- 断る／保留する：首を振る、立ち去る、後日また相談する。
- 提出する：品物を見せる、手渡す、目的の場所に置く。
- 手伝う：農作業や荷物運びなど、対象の行動を実際に行う。

**主人公に通常の日本語セリフを言わせることを前提としない。** UI上の操作表記はプレイヤーの使用言語で分かるようにしてよいが、宇宙語の会話の意味を先回りして明かさない。

### 5.2 依頼の目標と方法を分ける

「青い魚が必要」という依頼なら、魚は自分で釣っても、店で買っても、手持ちから渡してもよい。

ただし「一緒に魚を釣る」「決められた場所で実際に収穫する」など、**行動そのものが目的のクエスト**は例外。

| 本当の目的 | 達成方法の例 |
|---|---|
| 魚を3匹入手したい | 釣り、購入、在庫を渡す |
| 野菜を料理に使いたい | 自家栽培、種屋・商店で購入、手持ちを渡す |
| 大切な友達に花を渡したい | 花を用意し、指定相手へ届ける |
| 釣り名人と勝負したい | 実際に釣り勝負へ参加する |
| 壊れた設備を直したい | 素材を渡す、修理作業に参加する |

### 5.3 クエスト結果

- **達成**：求めていた行動が行われた。
- **別の反応**：似た品物、好みと異なる品物などに住民が違う反応を示す。
- **保留・未参加**：プレイヤーは他の活動を続けてもよい。
- **住民が別の方法で解決**：一定の状況では住民自身が行動したり、別の住民が助けたりする（提案）。

どの依頼に期限を設けるか、失敗・放棄の扱いをどうするかは【未決定】。

## 6. 日常のお願い【採用方向／提案】

### 6.1 主なバリエーション

| 分類 | 例 | 主に接続する遊び |
|---|---|---|
| 魚の納品 | 特定の魚・サイズの魚を集める | 釣り |
| 作物の納品 | 野菜・花・果物を渡す | 農業 |
| 鉱石の納品 | 鍛冶屋に鉄鉱石を届ける | 鉱山 |
| 生物の捕獲・観察 | 特定の宇宙生物を探す | 生き物取り |
| 配達 | 荷物や贈り物を別の住民に届ける | 住民交流 |
| 落とし物 | 村内でなくした品物を探す | 探索・観察 |
| 商品の注文 | 商店に特定の商品を並べる | 商店 |
| 買い物・仕入れ | 住民が必要な品物を入手する | 商店・村の生活 |
| 作業の手伝い | 畑仕事、荷運び、村の準備 | 農業・住民交流 |

### 6.2 日替わり掲示板【提案】

- 広場などの掲示板に、住民が宇宙語で依頼を掲示する。
- 依頼主が分かる署名・顔などを添える案。
- 住民本人が絵を描いていた場合のみ、絵も掲示する。
- 依頼は入れ替わり、主人公は好きな依頼を選ぶ。
- 報酬はお金、生活アイテム、道具素材などを中心にする。
- 依頼一覧を日本語の正解文に置換しない。

**日替わり更新は提案であり、すべてが24時間限定の依頼になるという決定ではない。**

## 7. 自発的なお手伝い【提案】

依頼ウィンドウを出さずとも、住民の状態や行動を見て手伝える。

**例**

- 家の前で重い荷物を運んでいる住民を手伝う。
- 落とした道具を拾って渡す。
- 農作業で困っている住民の畑を手伝う。
- 祭りの飾り付けが進まない住民に素材を届ける。
- 友達へ花を渡せず立ち止まっている住民を見て事情を探る。

この系統では「受注ボタン」を押したかどうかより、**プレイヤーが見た・気付いた・行動した**という出来事を重視する。

住民から感謝されたときの宇宙語が、ほかの日常会話で再び現れれば、言語推理の手掛かりになる。

## 8. 住民の暮らしからクエストが生まれる【提案】

### 8.1 住民は依頼待ちではない

住民はそれぞれ仕事、買い物、趣味、人間関係などに関する目的を持つ。必要な物が足りない場合、まず自分で探したり買い物をしたりすることもある。

**料理好きの住民の例**

1. 新しい料理を作ろうと思う。
2. 必要な野菜が手元にない。
3. 商店へ買いに行く。売っていれば購入する。
4. 売っていなければ、掲示板や主人公へのお願いにつながることがある。
5. 主人公が材料を渡せば料理を作り、翌日その料理が家に置かれているかもしれない。
6. 主人公が関わらなければ、別の材料で作ったり、別の住民に頼んだりする展開も考えられる。

### 8.2 生活の変化を残す

| 住民の目的 | 依頼の例 | その後の生活の変化 |
|---|---|---|
| 鍛冶屋が道具を作る | 鉱石の納品 | 完成した作品が工房に飾られる |
| 農家が珍しい作物を育てる | 種・肥料探し | 庭に新しい作物が育つ |
| 生物好きがペットを飼う | 宇宙生物探し | 家に実際のペットがいる |
| 花好きが庭を飾る | 花の納品 | 家の周囲が華やかになる |
| 修理屋が道具を直す | 修理素材を集める | 道具が直り、仕事が再開する |
| 住民が友達を祝う | 誕生日プレゼント探し | 当日の贈り物や反応が変化する |

**住民が自律的にどの範囲まで問題を解決するか、生活の変化をどの程度永続保存するかは未決定**。上記は企画上の体験例。

## 9. 住民固有の個別ストーリー【採用方向／提案】

### 9.1 住民ごとの題材

| 住民の特徴・仕事 | エピソード案 |
|---|---|
| 釣り名人 | 釣り勝負、思い出の魚、名人の技、釣りを続ける理由 |
| 鍛冶屋 | 自分の最高傑作を作ろうとする |
| 種屋・農業名人 | 昔育てていた珍しい作物を探す |
| 料理好き | 新しい料理を村のみんなに振る舞う |
| 生物研究家 | 希少な生物の生態を研究する |
| 引っ込み思案な住民 | 親しくなりたい相手へ気持ちを伝える |
| 旅行好き | ほかの村への引っ越しを悩む |
| 花好き | 大切な人との思い出の花を育てる |
| 商人 | 新しい取引先や商品を探す |

**趣味や性格は住民ごとに異なる。全員を同じ5話構成や同じ親密度条件に揃える必要はない。**

### 9.2 個別ストーリー例：青い花【提案】

**第1話「青い花」**：ある住民が商店で青い花を何度も購入する。主人公は花好きだと推測する。

**第2話「誰かのための花」**：その住民は別の住民の家へ花を持って行くが、家の前でためらい、帰ってしまう。

**第3話「小さなお願い」**：花を渡してほしいと頼まれる。言葉が分からなくても花と相手の家を指さす様子から推測できる。

**第4話「届けた花」**：花を届けると相手が喜ぶ。後日二人が一緒に過ごすことが増える。

**最終話「花の意味」**：交流が深まると、花に込められていた意味が分かる。例えば、昔からの友人へ感謝を伝えたかったという事情。

この話の要点は、**プレイヤーが最初に書いた「花が好き」というメモは間違いかもしれない**ということ。ゲームがそのメモを自動訂正することはない。

### 9.3 個別ストーリー例：釣り名人【提案】

1. 川で出会い、名人が身振りで釣り方を示す。
2. 何度も一緒に釣るうちに、釣り勝負が始まる。
3. 昔釣った珍しい魚について何度か話す。
4. 一緒にその魚を探す出来事や、釣りテクニックを教わる機会が生まれる。
5. 釣りを続ける理由など、本人の人生が分かるエピソードへつながる。

釣りの腕を上げる楽しさと、住民自身の物語の両方を成立させる。

## 10. 選択・分岐・プレイヤー不参加【提案】

**住民が友達の誕生日プレゼントを探している例**

| プレイヤーの行動 | 展開の例 |
|---|---|
| 相手の好みを調べて合う物を渡す | とても喜ばれ、印象深い思い出ができる |
| 別の品物を渡す | 予想と違う反応をされるが、その後の会話につながる |
| 手伝わない | 住民が自分でプレゼントを用意する可能性がある |
| 後から事情を知る | 住民との会話で当日の出来事を知る |

**最良結果だけが正解ではない**。プレイヤーが選んだ暮らし方と経験が、その星での思い出になる。

ただし、全依頼に複雑な分岐を設けることは決定していない。日常のお願いはシンプルに、重要な個別エピソードは反応や結果を充実させる構成が候補。

## 11. 依頼帳：宇宙語のまま残すクエスト記録【提案】

### 11.1 基本情報

| 欄 | 保存内容 | 注意点 |
|---|---|---|
| 依頼主 | 住民の顔、仮の呼び名など | 住民の本当の名前は自動で分かったことにしない |
| 原文 | 住民が話した宇宙語、掲示板の宇宙語 | 正解訳を自動併記しない |
| 手掛かり | **実際に**見せられた絵・物、身振りなど | UI側で勝手に正解アイコンを追加しない |
| 依頼を受けた場所 | 村の広場、住民の家など | 主人公が訪れた場所は記録可能 |
| 自由メモ | プレイヤーが考えた意味・仮説 | 間違った推測も保持する |
| 状態 | 進行中・完了など | 進行状況と翻訳の正しさを混同しない |
| 過去の記録 | 当時の原文・メモ・結果 | 後から読み返せる |

### 11.2 記録の例

- **依頼主**：住民 No.014（プレイヤーの仮称）
- **場所**：村の広場
- **宇宙語**：「ミラ ノク ポテラ！」（説明用。生成結果ではない）
- **実際に見せられた物**：青い花の絵
- **本人の自由メモ**：「青い花が必要？ 誰かへのプレゼント？」
- **状態**：進行中

プレイヤーはこの記録を見ながら、自分で依頼内容を推理する。

### 11.3 宇宙語辞書・住民辞典・顔付き付箋

- **宇宙語辞書**：気になる単語や文法の推測を登録。
- **住民辞典**：好きな物、仕事、行動、人間関係、昔の出来事を自由記録。
- **依頼帳**：依頼の原文・状況・自分の考え・進行を記録。
- **顔付き付箋**：住民が実際に残した文章や反応を、原文のまま関連資料へ貼り付ける。

同じ付箋や会話を複数の辞典から参照できる仕組みは【提案】。プレイヤーが記した推測と、ゲーム内部の真の意味を混同させない。

## 14. 住民の引っ越しとの連携【既存方向性／提案】

- 住民は引っ越してきたり、村を離れたりする。
- 引っ越し準備やお別れを手伝うイベントを用意できる。
- 途中まで親しくなった住民が引っ越しても、住民辞典・記録・付箋は残る。
- その後に手紙が届く、再訪する、ほかの住民との会話で近況が分かる、といった展開は【提案】。
- 一度教わった釣りなどのテクニックは、教えた住民が引っ越した後も使用できる方向。

**引っ越しによって未完了のエピソードをどう扱うか**、職人など必須機能の引き継ぎ、引っ越し頻度・条件は【未決定】。とくにロケット修理の必須サービスは住民の移動と矛盾しないようにする。

## 18. 宇宙語生成とローカライズの考え方【技術設計の提案】

### 18.1 依頼の意味データと宇宙語の表示を分離

例えば、ゲーム内部には次の「意味」がある。

```text
依頼主：住民A
対象：青い魚
数量：3
目的：料理に使う
依頼の意図：指定アイテムの入手
```

この情報を、その星のシードで定まる語彙・語順・文法に基づき宇宙語として表現する。

- 星Aと星Bでは、同じ依頼でも言葉や語順が変わり得る。
- 依頼の意味・必要な行動は内部で一貫して管理する。
- 同じ宇宙語・文法が別の会話にも繰り返し登場し、推理に役立つ。
- プレイヤーのUI言語が変わっても、同じ星なら同じ宇宙語になる方向。
- ゲーム内部の正解データを、プレイヤー辞書や依頼帳へ自動転記しない。

具体的なデータ構造・会話生成アルゴリズム・辞書UIは【未決定】。

### 18.2 国際展開

- 「ね」「よ」など日本語固有の細かな終助詞や、冠詞・文法上の性別に解読を依存させない。
- 意味の違いが各言語で伝わる内容を優先する。
- 翻訳テキストが必要なUIと、プレイヤーが解読する宇宙語を分離する。
- プレイヤー自身が書いた自由メモを、内部的な正答と同一視しない。

## 19. 具体的なプレイの流れ【提案】

### 19.1 日常のお願い：青い魚

1. 料理好きの住民が、宇宙語で何かを頼む。
2. 青い魚の現物や絵を見せるかどうかは、その住民の行動による。
3. プレイヤーは釣る・買う・持ち物から渡すなど好きな方法で用意。
4. 住民に渡すと反応が返り、条件を満たせば達成となる。
5. 後日、住民がその魚を使った料理を作っているかもしれない。
6. 当時の原文・手掛かり・自分の推測が依頼帳に残る。

### 19.2 自発的なお手伝い：荷物運び

1. 住民が家の前で大きな荷物を運ぼうとしている。
2. 主人公が自分から近づき、荷物を運ぶ操作をする。
3. 住民が感謝の宇宙語を話す。
4. 別の日に同じ語が再登場し、意味を推理できる。
5. その住民の家の模様替えが進むなど、小さな生活の変化が残る。

### 19.3 住民固有の出来事：青い花

1. 商店で青い花を買う住民を何度も見かける。
2. 住民辞典に「青い花が好き？」と記入。
3. 別の家の前で花を持ってためらう場面を目撃する。
4. 花の配達を頼まれる。言葉が分からなくても身振りで気付ける。
5. 届けたあと、二人の関係に変化が生まれる。
6. さらに宇宙語が分かると、花に込められた意味を理解できる。

## 22. 今後さらに詰めるテーマ

1. **住民の生活データ**：仕事・好み・予定・人間関係から、どの程度自律的に依頼が生まれるか。
2. **依頼帳の操作感**：原文保存・自由メモ・付箋・辞典間参照をどう扱うか。

4. **住民固有ストーリー**：話数を固定せず、各人物ならではの展開・反応・余韻をどう設計するか。
5. **イベントの分岐**：主人公不参加時、別の品物を渡したとき、引っ越し後の扱い。
6. **宇宙語との公平な連携**：解読できなくても体験でき、解読すると理解が深まる構成。
7. **村イベントの内容**：四季なしの暦・誕生日・催し・引っ越しとの接続。
8. **マルチ時の権限**：ゲストが依頼・住民の生活にどこまで関われるか。

## 23. 企画の核となる結論

**『宇宙人の星』のクエストは、「依頼を達成して報酬を受け取る」だけではない。**

住民が買い物をし、働き、仲良くなり、悩み、引っ越していく。その生活の中に主人公が入り、時には手伝い、時には見守り、宇宙語を少しずつ理解する。

最初は何も分からなかった行動が、後から住民の大切な気持ちだったと気付く。自分の辞書や住民辞典を読み返すと、暮らしてきた日々の意味が変わって見える。

**「住民と暮らす → 依頼や出来事に出会う → 自分なりに行動する → 言葉と相手を知る → その後の暮らしが変わる」**。

この循環を、クエスト・住民イベントの中心にする。

*本書はv0.2時点の企画整理用であり、提案を自動的に確定仕様へ格上げするものではない。*
