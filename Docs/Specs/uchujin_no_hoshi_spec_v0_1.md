- **作成日**：2026年10月14日
- **ステータス**：企画整理・独立プロジェクト移行用
- **仮タイトル**：宇宙人の星（正式名称未決定）
- **資料の位置付け**：これまでの会話を引き継ぐための暫定仕様。未確定の提案を決定事項として扱わない。

## 0. この仕様書の読み方

本文では以下の区分を使用する。

- **【決定】**：ユーザーが明確に採用した内容、または明確に否定した内容。
- **【方向性】**：会話上の方針として概ね一致しているが、詳細は未確定の内容。
- **【提案】**：会話で出たアイデア。採用が確定していない内容。
- **【未決定】**：今後設計・検証が必要な内容。

**重要：新プロジェクトでは、本書を出発点とする。ただし、【提案】を勝手に確定仕様に昇格させない。面白さを高める改善案は歓迎するが、根幹の方針を変更する際は区別して提示する。**

## 1. 企画概要

### 1.1 コンセプト

**【決定／方向性】**

別宇宙から来た主人公が、宇宙人の暮らす未知の星に不時着する。最初は住民の言語を理解できないが、さまざまな状況で会話を聞き、身振り、行動、物、前後関係を観察し、**自分でメモを取りながら単語や文法を解読**していく。

その星で生活し、商店経営などでお金を稼ぎ、**宇宙船（ロケット）の修理部品を購入して、故郷の星へ帰る**ことが大きな目標となる。

言語の解読と、住民との交流、商店を中心とする生活シミュレーションを組み合わせる。

### 1.2 参考にするゲームの役割

| 参考作品・企画 | 参考にする方向性 | 注意点 |
|---|---|---|
| どうぶつの森 | のんびりした生活、住民との交流、プレイヤーの自由 | マップや収集要素を無制限に拡大する方針ではない |
| 牧場物語 | コンパクトな生活圏、日々の生活と住民関係 | 農業を唯一の中心要素にするわけではない |
| Stardew Valley | 密度のある町・生活要素と、明確な目標の両立 | 同作の全システムを移植するわけではない |
| 宇宙商店（別企画） | 宇宙人との商売、商品・注文・接客など | 既存企画の全仕様をそのまま採用するわけではない |

**【方向性】** 規模感は「どうぶつの森のような広がり」より、**牧場物語／Stardew Valleyに近い、コンパクトで密度の高い生活ゲーム**を目指す。

### 1.3 本作独自の魅力

1. 住民の言葉が最初は分からない。
2. 日々の暮らしや商売を通じて、単語と文法の意味を推理する。
3. 語彙だけでなく**文法も星のシードごとに異なる**ため、星が変われば攻略知識がそのまま通用するとは限らない。
4. 自分で書いた辞書を、マルチプレイでは**渡しても渡さなくてもよい**。
5. ロケットを修理して帰還するという、明確な到達目標がある。

## 2. 舞台・主人公・ストーリー

### 2.1 導入

**【決定】**

- 主人公は**別宇宙から来た人**。
- 宇宙人の暮らす星に**不時着**する。
- 現地の言葉は最初、理解できない。
- 故郷の星へ帰るため、壊れた宇宙船を修理する必要がある。

**【未決定】** 主人公の外見・出自の詳細、故障の原因、村の住民が主人公をどう受け入れるか、主人公の初期所持品、導入演出。

### 2.2 物語の方向性

**【提案】**

- 初めは「帰るためにお金を稼ぐ」が主な目的だが、言葉を覚え、住民と仲良くなることで、星への愛着が生まれる。
- クリア時の別れの場面は、プレイヤーがどれだけ言語を理解したかによって受け取り方が変わり得る。
- 帰還後も星を再訪して生活を続けられる仕組みは候補。ただし、エンディング後の仕様は未確定。

**【方向性】** 言語を100％解読することはクリアの必須条件にしない。商売や交流の深さはプレイヤーの選択に委ねたい。

## 3. 基本ゲームループとクリア条件

### 3.1 主なサイクル

**【方向性】**

1. 村や周辺で日常生活を送り、住民・商店の客・環境に接する。
2. 会話の状況から宇宙語を推理し、メモや辞書を更新する。
3. 商店経営やその他の生活活動でお金を稼ぐ。
4. 必要に応じて家・店・生活環境を充実させる。
5. 修理用の部品を購入して、宇宙船の修理を進める。
6. 修理を完成させ、故郷へ帰還する。

### 3.2 目標と自由度

**【決定】** 最終目標は、**お金を集める → 部品を買う → ロケットを直す → 自分の星に帰る**こと。

**【方向性】** お金稼ぎの手段に選択肢を持たせ、言語解読も日々の生活も強制的な一本道にしない。

**【未決定】** 修理部品の種類・数・値段、修理の工程、通貨名、経済バランス、想定クリア時間、エンディング分岐、クリア後の継続プレイ。

> **注意**：過去の会話に出た「部品5種類」「合計20万」といった数値は説明用の仮例であり、決定仕様ではない。

## 4. 生活ゲームの規模と遊び

### 4.1 マップ規模

**【方向性】**

- 広大な惑星探索よりも、**小さな村とその周辺を充実させる**。
- 同じ住民と日常的に何度も出会い、会話が積み重なる構成を重視する。
- 住民の頭数やエリア数を増やすより、生活・性格・関係性・会話の密度を重視する。

**【未決定】** マップ面積、エリア数、住民数、季節・天候、ゲーム内の日付進行、建物配置、2D／3D。

### 4.2 商店経営

**【決定／方向性】** 別企画『宇宙商店』のシステムを生活ゲームと組み合わせる。**商店経営は中心となる金策・住民交流の候補**。

- 注文や接客が、宇宙語に触れる自然な機会になる。
- 商品や数量、依頼内容など、**状況から意味を推測しやすい語彙**と相性がよい。
- 言語の理解が進むことで接客の解像度が上がるようにする。

**【未決定】** カウンター型かセルフ販売型か、倉庫管理、仕入れ、営業時間、拡張、常連客、在庫・価格の仕組み、『宇宙商店』から再利用する具体的な機能。

### 4.3 その他の生活要素

以下は**採用を検討した要素**であり、全ての実装を決めたわけではない。

| 要素 | 現状 | 企画上の役割 |
|---|---|---|
| 住民との日常会話・交流 | 【方向性・重要】 | 言語を学ぶ場／住民に愛着を持つ場 |
| 家・家具・生活環境 | 【提案】 | 稼いだお金の使い道、暮らしの自由度 |
| 農業・採集 | 【提案】 | 金策・生活・語彙学習の一手段 |
| 釣り | 【提案】 | のんびりした日常、金策、住民との交流 |
| 虫取り | 【提案】 | のんびりした日常、金策、住民との交流 |
| 生物図鑑・博物館 | 【未採用／低優先の提案】 | 収集拡張。規模を広げ過ぎないよう注意 |
| 大規模な大会・イベント | 【未採用／低優先の提案】 | 生活の変化。ただし初期仕様に必須ではない |

**【方向性】** 釣り・虫取りを採用する場合、複雑なミニゲームを増やすより、宇宙らしい生態と小さな生活圏の密度を重視する。言語を学ばないと釣りができない、というような過度な進行制限は避ける。

## 5. 宇宙語システム（本作の核）

### 5.1 基本原則

**【決定】**

- プレイヤーは、最初から住民の言語を理解できない。
- 会話はシチュエーション、行動、身振り、物、繰り返しなどを手掛かりに解読する。
- **プレイヤー自身がメモする**遊びを大切にする。
- **単語だけでなく文法も、シードごとに変える**。
- 宇宙語は、単なる日本語の単語置換ではなく、筋の通った言語として成立させたい。

**【方向性】** 意味の通じる会話を学習できるよう、生成ルールは一貫性を持たせる。無秩序な文字列や不規則な例外ばかりで推測不能にしない。

### 5.2 シードで変動させる要素

| 項目 | 扱い | 補足 |
|---|---|---|
| 単語の発音・綴り | 【決定】ランダム化対象 | 同じ概念でも星によって異なる |
| 語順（主語・目的語・動詞など） | 【決定】ランダム化対象 | 文章構造の推理につながる |
| 助詞・格表現の方式 | 【方向性】ランダム化対象 | 有無、位置、接辞などが変わり得る |
| 否定の表現 | 【方向性】ランダム化対象 | 「しない」「ない」など |
| 疑問の表現 | 【方向性】ランダム化対象 | 語順や疑問要素など |
| 時制・時間表現 | 【方向性】ランダム化対象 | 過去・現在・未来など |
| 希望・依頼の表現 | 【方向性】採用 | 「したい」「してほしい」など意味が変わるもの |
| 所有の表現 | 【方向性】採用 | 「私の」「あの人の」など |
| 複数形の仕組み | 【提案】 | 必要性・難度を要検討 |
| 発音規則・音の組み合わせ | 【提案】 | 言語ごとの響きの違い |
| 敬語体系・話し方の個性 | 【未決定】 | 複雑さを増やさずに表現する方法を検討 |

### 5.3 原則として採用しない文法要素

**【決定】** 国際的なローカライズを見据え、意味の解読にほぼ寄与しない細かい要素は削る。

- **「ね」「よ」「な」など、日本語特有の細かなニュアンスを足す終助詞**は基本的に不要。
- **冠詞（英語の a / the に相当する要素）**は基本的に不要。
- **文法上の性別で名詞や形容詞を変化させる仕組み**は基本的に不要。

> 注意：「ね」「よ」が不要だからといって、すべての付属語をなくすわけではない。**否定・疑問・時制・格・希望・所有など、文の意味を大きく変える要素は残す**。

### 5.4 宇宙語の生成方法

**【提案：技術設計の方向性】**

1. 会話の「意味」を、特定の自然言語に依存しない内部データで表現する。
2. 各星のシードから、語彙辞書・語順・文法ルールを決める。
3. 会話の意味データを、その星の言語ルールに従って宇宙語へ変換する。
4. ゲーム内では原則として宇宙語を表示し、プレイヤーが自分で理解していく。
5. 発見したと本人が判断した意味は、プレイヤー自身が辞書に記録する。

**重要**：上記は実装アーキテクチャの有力候補であり、具体的なデータ形式、パーサー、文生成アルゴリズム、単語数、文法パターン数は未決定。

### 5.5 プレイ上の解読体験

**【方向性】**

- 商店で客が商品を指す、数量を手で示す、住民が行動する、といった**状況の手掛かり**を用意する。
- 同じ語や文法が複数の場面で現れ、仮説を確かめられるようにする。
- 文法を推理できても、単語を全て知っている必要はない。逆も同様。
- 暗記量ではなく「理解できた」という体験を重視する。

**【提案】** 自分で登録した訳語を会話に併記・置換する機能。ただし、プレイヤーの推測が誤りでも、ゲームが勝手に正しい意味へ修正しない設計が望ましい。

**【未決定】** ヒントの強さ、推測に対する正誤判定の有無、辞書UI、語彙数、難易度、同音異義語・多義語、文法の例外、解読率の表示方法。

## 6. メモ帳・辞書システム

### 6.1 根本方針

**【決定】**

- **自分で単語や文法の意味を書き留める**ことが重要な遊び。
- メモは、システムが保証した正答集でなく、**プレイヤーの知識・推測の記録**として扱う。
- マルチプレイ時には、辞書をほかのプレイヤーへ渡す遊びができる。
- **辞書の自動配布はしない**。渡すかどうかはプレイヤーが決める。

### 6.2 辞書に記録できそうな内容

**【提案】**

- 宇宙語の単語・表現
- 自分が推測した意味
- 文法の法則や語順に関する自由メモ
- 例文・気づいた場面
- 「仮説」「自信がある」など、任意の本人用マーク

**【未決定】** 自由入力だけか、構造化項目も用意するか、メモの上限、検索、タグ、表示連動、コピーや編集履歴。

### 6.3 間違った解釈も残せること

**【方向性】** 勘違いもゲーム体験の一部。間違った辞書の記載をゲームが自動的に正解へ書き換えない。住民の会話や出来事を通じて、プレイヤー自身が訂正できるようにする。

## 7. マルチプレイと辞書の受け渡し

### 7.1 星への訪問

**【決定／方向性】**

- 自分の星をマルチプレイで開き、別プレイヤーが訪問できる構想。
- 訪問先では**その星の言語**を使う。
- 他プレイヤーは辞書がなければ、自分の推理で言葉を理解していく。

### 7.2 辞書の共有ルール

**【決定】**

1. **訪問者に辞書を自動配布しない。**
2. 星の持ち主が**辞書を渡さない**遊び方を選べる。
3. 持ち主が**辞書を手渡す**遊び方も選べる。

**【提案】**

- プレイヤーが書いた内容を共有するため、**間違った情報・わざと嘘を書いた辞書**を渡す遊び方も成立させる。

- 辞書をコピーして渡し、元の辞書を失わない。
- 単語やページの一部だけを共有する。
- 受け取った辞書を自分の辞書に取り込むか、別冊として保存するか選べる。
- ホストとゲストがそれぞれ新たな解読を進められる。

**【未決定】** 受け渡しUI、複製方式、コピー制限、ゲストの書き込み権限、解読記録の同期、再訪時の辞書保存、辞書を悪用した荒らし対策。

### 7.3 ネットワーク技術

**【未決定】** 本作で使用するゲームエンジン、ネットワーク方式、プレイ人数、ホスト権限などは正式決定していない。

※ほかの開発企画ではUnityやEOS P2Pを使っているが、**本作への採用を既成事実にしない**。採用する場合は星のシード・言語・住民状態・辞書データの責任範囲を明確にする。

## 8. 多言語ローカライズ

### 8.1 大前提

**【決定／方向性】** 日本語以外の国・地域でも楽しめる作品を想定する。日本語の「来て」「来てね」「来てよ」の細かな違いをそのまま宇宙語に再現する必要はない。

言語によって丁寧さや感情の表し方は異なるため、**世界共通で意味の差が伝わりやすい文法・語彙を優先**する。

### 8.2 ローカライズ設計

**【提案：有力な実装方針】**

- 宇宙語は、プレイヤーの使用言語とは独立した一つの架空言語として扱う。
- 同じ星なら、日本語版・英語版などでも原則として**同じ宇宙語の単語・文法**が現れる。
- 会話の意味を内部の共通データとして持ち、UI、説明、必要なヒントだけを各言語でローカライズする。
- プレイヤーが自由入力したメモは、**自動翻訳された正解**と混同しない。異なる言語のプレイヤーへの共有方法は別途設計する。

### 8.3 未解決の課題

**【未決定】**

- 各言語圏で同じくらい推理しやすいヒントを用意できるか。
- 語順の違いや文法区別を、各言語版で不公平なく学べるか。
- プレイヤーの手書き辞書を、異なる表示言語の相手にどう渡すか（原文のまま／任意翻訳／意味タグなど）。
- ローカライズ対象言語と各言語での品質検証。

**禁止したい設計ミス**：日本語を基準に語尾だけ置換し、他言語では成立しない文法問題を作ること。

## 9. 住民・会話・生活の作り込み

### 9.1 住民の役割

**【方向性】** 住民との接触は、単なるクエスト受注ではなく、生活の中心となる。

- 商店に客として来る。
- 村で行動する。
- 会話の前後関係から言葉の意味を推測させる。
- 言語を覚えるほど、住民の性格や事情を理解できる。

**【提案】** 住民ごとの生活スケジュール、性格、交友関係、エピソードを設定する。最初は理解できなかった何気ない発言の意味が、後から分かるようなエピソードを用意する。

**【未決定】** 住民数、性格の種類、固定シナリオか動的会話か、関係値・好感度・恋愛・結婚の有無、言語解読の難度と住民会話量のバランス。

### 9.2 演出

**【方向性】** 細かな終助詞で表現しない丁寧さや感情は、可能なら表情・仕草・行動・会話内容などでも伝える。ゲームを進めても「暮らしていて楽しい」ことを重視する。

## 10. 初期開発で特に守りたい設計原則

1. **スローライフが主役の一つ**：言語解読だけのパズルゲームにはしない。
2. **言語は意味を持つ**：単語を暗記するだけでなく、文法と状況から推測できる。
3. **シード差は本物**：単語だけでなく、文法の構造も変わる。
4. **プレイヤーのメモが主役**：推測・誤解・訂正をゲームが奪わない。
5. **辞書を配らない自由**：マルチプレイで訪問者に辞書を渡すかどうかは任意。
6. **遊びを広げすぎない**：博物館や大量の収集、広大な探索を安易に必須化しない。
7. **クリア目標を見失わない**：金策 → 修理部品 → 宇宙船修理 → 帰還。
8. **多言語対応を初期設計から考える**：日本語独自の語尾表現を言語ゲームの必須問題にしない。
9. **未決定事項を勝手に確定しない**：この資料は完成仕様書ではなく、設計の土台。

## 11. 実装時の検証項目（提案）

本格開発時には、少なくとも以下を検証する。

### 言語生成

- 同じシードを読み込むと、同じ語彙・文法が再現される。
- 異なるシードでは、語彙だけでなく一部の文法ルールも変わる。
- 生成された会話の意味が破綻しない。
- 初見でも状況から推理できるよう、必要な手掛かりが用意されている。
- プレイヤーが間違った意味を書いても、辞書が勝手に修正されない。

### マルチプレイ

- ゲスト入室時に**辞書が自動で渡されない**。
- 訪問先の星の言語はホスト星の設定と一致する。
- 辞書を受け取らずに遊べる。
- 明示的に辞書を渡せる。
- 辞書内の誤った推測や自由メモも、ゲームが正解に改ざんせず扱える。

### ローカライズ

- 日本語版と他言語版で、同じ宇宙語のルールを解読できる。
- 言語固有の語尾・冠詞・文法性に依存する問題を必須にしない。
- 手書きメモと、内部的な正しい意味が混同されない。

### 基本ループ

- 宇宙語が完全には分からなくても、日常生活と金策を進められる。
- 修理部品を購入・修理することで、故郷への帰還に到達できる。
- 会話を解読する行為が、単なる翻訳作業ではなく生活体験を豊かにする。

## 13. これまでの会話から明確に修正・除外したこと

引き継ぎ時に誤解されやすいため、特に明記する。

- **辞書の自動配布はしない。** 過去に提示された「星へ来た人に自動プレゼント」はユーザーが明確に否定した。
- **日本語の「ね」「よ」などを細かく再現しない。** 多言語化とゲーム上の意味の明確さを優先する。
- **冠詞を基本仕様に含めない。** 推理の面白さに対する負荷が高いと判断。
- **どうぶつの森の全要素を網羅しない。** 牧場物語／Stardew Valley寄りの、コンパクトな暮らしを志向する。
- **自動的に正しい翻訳を配るゲームにしない。** プレイヤーが推測し、メモする過程が重要。
- **説明のために挙げた部品価格・部品数・言語例は決定仕様ではない。**

## 14. 次プロジェクトへの引き継ぎ文

> このプロジェクトでは、仮題『宇宙人の星』を開発する。主人公は別宇宙から宇宙人の星に不時着し、住民の言葉を知らない状態から生活を始める。住民との会話や商店経営などの日常を通じて、単語や文法を自分でメモして解読する。宇宙語の語彙・語順・文法は星のシードによって変わる。世界観と生活の密度を重視し、ゲームの規模は牧場物語／Stardew Valley寄りに抑える。最終目標はお金を稼いで宇宙船の修理部品を買い、故郷へ帰ること。マルチでは他プレイヤーの星を訪ねられ、辞書を渡すかどうかはプレイヤーが自由に決める。自動配布はしない。ローカライズを考慮し、「ね」「よ」のような細かな終助詞や冠詞は原則採用しない。今後の設計では決定事項と提案を区別し、言語解読・住民交流・商店経営の面白さを最優先に磨く。
