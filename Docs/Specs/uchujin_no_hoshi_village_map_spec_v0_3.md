## 0. 仕様の区分と設計原則

本文では次の区分を用いる。

- **【決定・既存方針】**：これまで明確に採用された根幹の仕様・方針。
- **【採用方向】**：会話の流れから優先する方向だが、実装の細部は調整可能なもの。
- **【提案】**：面白さを高めるための追加アイデア。採用は未確定。
- **【未決定】**：今後の設計・比較・検証が必要なもの。

**基本コンセプト**：主人公は別宇宙から未知の星に不時着する。知らない宇宙語を話す、かわいい宇宙人たちの村で暮らし、釣り・生き物取り・採掘・農業・クエスト・商店を楽しみながらお金を稼ぎ、宇宙船を修理して故郷へ帰る。言語の完全解読はクリア条件ではない。

村・マップの役割は、単に各遊びの入り口を並べることではない。**住民の日々の暮らし、自然の変化、言語を理解する手掛かりが一体となり、繰り返し訪れるほど愛着が深まる星**を作ることにある。

### 設計で優先すること

1. **星ごとの発見**：地形・村の構造・施設配置・初期住民・宇宙語がシードに応じて変わる。
2. **住民の生活**：住民は同じ道や施設を実際に利用し、主人公の不在時にも活動する。
3. **暮らしの変化**：家具や庭、住民構成、ペット、公共空間などに暮らしの結果が残る。
4. **生活ゲームとしての面白さ**：六つの主要活動を無理なく行き来できる。
5. **言語解読の機会**：最初は知らない地名、場所、住民の行動を観察・記録し、理解を深める。
6. **自由度**：プレイヤーごとに活動・経路・住まい方・発見の順序が異なる。
7. **四季なし**：【決定・既存方針】季節を春夏秋冬に分けない。変化は昼夜・天候・環境・住民の出来事などで作る。

## 1. ワールドシードと星の生成

### 1.1 ワールドシードの役割【採用方向】

新しい星を始めるときにワールドシードを決め、そのシードからその星の初期状態を生成する。

| 生成対象 | シードによる差異 | 状態 |
|---|---|---|
| 宇宙語 | 語彙・語順・文法・発音規則 | **決定・既存方針** |
| 地形 | 山・丘・谷・平野・高低差、地形のつながり | **採用方向** |
| 水辺 | 川・池・湖・海岸線・橋が必要な場所 | **採用方向** |
| 自然 | 森・草原・植物の分布、景観 | **採用方向** |
| 村 | 広場、住宅区画、道路、橋、休憩場所 | **採用方向** |
| 生活施設 | 鍛冶屋・種屋・各店・伝言広場等の配置 | **採用方向** |
| 主人公の拠点 | 自宅・農場の位置、区画形状 | **採用方向** |
| 鉱山 | 入口の場所、各階層の基本地形 | **採用方向** |
| 宇宙船 | 不時着地点、周辺の自然・道路 | **採用方向** |
| 初期住民 | 顔ぶれ・住宅・仕事・初期の人間関係 | **採用方向（一部は提案）** |
| 生物分布 | 既存50種類の生息場所・出現傾向 | **採用方向** |
| 植生や配色 | 植物・岩・地面の見た目の差 | **提案** |

### 1.2 完全ランダムにするのではない【採用方向】

- 同じ施設・同じ道の配置になる固定マップではなく、**地形と村の構造そのものが星ごとに異なる**。
- ただし、建物を無秩序にばらまかない。山、川、道、住宅、店の位置には地理・生活上のつながりを持たせる。
- どの星でも、これまで設計した六つの主要生活コンテンツを遊べる場所が存在する。
- 施設や拠点が地形によって孤立したり、進行不能になったりしないようにする。
- **川中心・海岸中心・湖中心**などは完成形の例であり、固定された三つのテンプレートから選ぶ仕様ではない。

### 1.3 同じシードと、生活の結果【採用方向】

- 同じ生成バージョンと同じワールドシードなら、**開始時の星の初期状態**を再現できるようにする。
- ゲーム開始後の住民の行動・引っ越し・商店の購入履歴・農場づくり等は、そのプレイの世界状態として保存する。
- そのため、同じ初期シードでも、生活を進めた後は違う歴史を持つ星になり得る。
- 生成後の星の宇宙語・地形を、ゲームのアップデートを理由に勝手に変化させない。

### 1.4 生成処理の分離【提案：技術設計】

一つのワールドシードから、少なくとも **地形／村／初期住民／宇宙語／自然・生物** などの独立した生成系列を派生させる。ある領域の生成アルゴリズムを改修しただけで、無関係な宇宙語や初期住民がすべて変わることを防ぐ。

生成に使用したバージョンと初期生成結果、ゲーム開始後の変更差分の保存方式は技術詳細設計で決める。

## 2. マップ全体の考え方

### 2.1 一つの村と周辺の生活圏【既存方針】

広大な惑星全域を巡るオープンワールドではなく、**一つの村とその周辺を中心とする密度の高い生活ゲーム**を目指す。村・農場・住宅・森・水辺・鉱山・不時着地がつながり、何度も行き来する。

### 2.2 主なエリア（概念上の7分類）【採用方向】

| エリア | 主な場所・施設 | 主要な遊び |
|---|---|---|
| ① 村の中心・商業エリア | 広場、主人公の商店、鍛冶屋、種屋、修理屋、日用品店、伝言広場 | 買い物、商店経営、住民交流、伝言・依頼 |
| ② 住宅地 | 住民の家、庭、ベンチ、公園、生活路 | 住民観察、家への訪問、引っ越し、個別ストーリー |
| ③ 主人公の自宅・農場 | 自宅、畑、果樹、倉庫、生物の住み場所 | 農業、飼育、加工、自由なレイアウト |
| ④ 森・草原 | 林、花畑、池、木陰、散歩道 | 採集、生き物取り、住民との遭遇 |
| ⑤ 川・池・海岸 | 川、湖、水辺、桟橋、砂浜 | 釣り、水辺の生き物取り、散歩 |
| ⑥ 山・鉱山 | 鉱山入口、岩場、地下約10階層 | 採掘、鉱石集め、鉱山生物 |
| ⑦ 宇宙船の不時着地 | 故障した宇宙船、修理作業場所、周辺の道 | メインストーリー、修理進行、帰還 |

これは**便宜上の分類**であり、七つの独立マップにするとは限らない。例えば、住宅の横に小さな池がある、森の中に住民の家がある、商店街から川が見える、といった重なりを許容する。

### 2.3 三つの生活圏としての見方【提案】

- **にぎやかな中心部**：広場・商業施設・仕事・待ち合わせ。
- **落ち着いた住居・農業地域**：自宅・住民の家・庭・畑・ペット。
- **自然と冒険の周辺地域**：森林・水辺・山・鉱山・生き物。

これらが日常の通行によって行き来されることが重要。専用コンテンツごとに住民の姿が消えるような分断は避ける。

## 3. 地形・道路・橋の生成【採用方向】

### 3.1 地形のつながり

- 山・高台・谷・平地・水辺に地理的なつながりを持たせる。
- 例えば、山から流れた川が森や村を通り、池や海へつながる地形があり得る。
- 川・湖・海岸の規模と位置は星ごとに変える。
- 見晴らしの良い高台、木陰、小さな花畑など、住民が好める場所を配置できる。

### 3.2 道路網と生活動線

- 広場、住宅、商店、農場、鉱山、釣り場など、必要な施設は道でつなぐ。
- 道は一方通行の一本道にせず、**複数の経路・橋・近道**を作る。
- 自宅から村へ、村から釣り場へなど、日常の行き来は気軽に行えることを重視する。
- 同時に、森を通る遠回りには生き物や住民との出会いなど、別の価値があってもよい。
- 住民は装飾上の道を歩くのではなく、生成された実際の経路で目的地へ移動する。

### 3.3 地形による星ごとの生活差

| 地形・道路の特徴 | 生まれ得る生活の違い |
|---|---|
| 川の中央に橋がある | 橋周辺が人の集まる場所になる |
| 海岸に住宅が多い | 仕事帰りに海辺へ寄る住民を見かけやすい |
| 森に沿った住宅街 | 散歩や生き物観察の機会が多い |
| 大きな湖を囲む村 | 湖畔が待ち合わせ場所になる |
| 鉱山まで山道が続く | 採掘師の往復や道中の遭遇が特徴になる |
| 道が複数の広場につながる | 住民の集まる場所が一カ所に偏らないことがある |

地形が違うだけでなく、**住民がどこを通り、誰と会い、何をするか**にも影響することを目指す。

## 4. 村の中心・商店街・伝言広場

### 4.1 広場【採用方向】

- 住民が待ち合わせ、休憩、会話、イベントを行う生活の中心。
- 村の象徴として、不思議な大きな木などのランドマークを置く案がある。【提案】
- 時間帯や天候によって、集まる住民や見た目が変わる。
- 釣果を見せ合う、買い物帰りに立ち話をする、新住民を歓迎するなど、日常の出来事を起こす。

### 4.2 主人公の商店【既存方針】

- 商品を棚に並べ、価格を設定すると、住民が自分で商品を選び**自動購入**する。
- 主人公の常時店番や、毎回のカウンター注文を必要としない。
- 購入した住民は、食材・家具・花・生物などを自分の生活で使用することがある。
- 店の品揃えが住民の行動や村の景色に影響する。
- **古い「文字の顔付き付箋」方式は採用しない**。最新方針では、宇宙生物**マネピによる音声・仕草の伝言**を活用する。

### 4.3 伝言広場【提案・既存タブレット案と連携】

- マネピが住民の依頼や伝言を覚え、声と仕草で再現する。
- 主人公は再現を聞き、必要ならタブレットへ音声記録を残す。
- 宇宙語の意味を自動翻訳しない。
- 商店や住宅の近くなど、住民が利用しやすい場所に設ける。

### 4.4 その他の生活施設

鍛冶屋、修理屋、種屋、日用品・釣り具等の店舗を設ける方向。建物の正確な種類・数・店舗の同居／分離、営業時間等は未決定。

## 5. 住宅地・住民の家・庭

### 5.1 星ごとに住宅区画も変える【採用方向】

- 住宅を一つの密集区画に限定せず、広場周辺・川沿い・森の近く・高台など、地形に応じて配置する。
- 家の外観・大きさ・庭・室内には住民の個性を反映する。
- 同じ種族の宇宙人が必ず同じ家に住むわけではない。趣味や性格の違いも見た目に反映する。
- 初期住民、どの家に誰が住んでいるかはシードに応じて変化する方向。

### 5.2 住民の生活が家に残る【既存の住民生活案と連携】

| 住民の行動・個性 | マップや家の変化例 |
|---|---|
| 花を買う・育てる | 庭や室内に花が増える |
| 家具を購入する | 室内の家具・装飾が変わる |
| 生物を飼う | ペットや飼育場所が増える |
| 釣り・収集が好き | 道具や釣果、収集物を飾る |
| 引っ越しを決める | 荷物をまとめ、庭・家の様子が変わる |
| 新しい住民が入る | 家具や庭が新しい住人の好みに変わる |

### 5.3 引っ越しとの連携【既存方針】

- 住民は引っ越してきたり、引っ越していったりする。
- 引っ越し前には荷物を整理し、近所への挨拶や別れの行動を取ることがある。
- 空き家には新しい住民が入居できる。
- 引っ越した住民との記録は住民辞典に残り、再訪やマネピの伝言を受け取る展開も候補。
- 同時居住**20〜30人程度**、総登場住民**100人以上**は過去の**規模提案**であり確定値ではない。

### 5.4 家への訪問【提案】

住民が在宅しているときに訪問し、家の中の様子や趣味の品、会話から住民について知る。訪問への反応は親しさ・時間帯・住民の状況などで変わる。家の中の飾りが、宇宙語や住民辞典に記録する手掛かりとなる。

## 6. 主人公の自宅・農場

### 6.1 自宅・農場の配置【採用方向】

- 村から無理なく往復できる場所に、主人公の自宅と農地を配置。
- 農場の形・周辺地形・アクセス路はシードで変化する方向。
- 農地はプレイヤーが自由にレイアウトできる構想。

### 6.2 農場の構成【既存の農業案と連携】

- 自宅、畑、花畑、果樹、倉庫、加工スペース、宇宙生物の住み場所・池など。
- 種まき、水やり、収穫を行い、農場の成長に応じて広げたり、配置を変えたりできる。
- **スプリンクラー等の機械的な自動化に代わり、宇宙生物が農作業を手伝う**構想を重視。
- 例えばミズプクが水やり、ホリモグが耕作、モギモギが収穫、ハコバチが運搬する。
- 生物の住み場所や組み合わせによって、働く範囲や農場の景色が変化する。
- 住民が農場へ遊びに来て、作物や飼育中の生物に反応する。

### 6.3 レイアウトの自由

- 野菜中心の農場、花畑、果樹園、生物の飼育中心など、多様な使い方を許容。
- 自動化の配置効率だけでなく、**自分の好きな景色を作る遊び**を重視。
- 農場に池や花畑を作ると、生息条件に合う野生の宇宙生物が集まる可能性がある。【提案】

## 7. 森・草原・川・池・海岸と生態系

### 7.1 自然を「採集用の背景」にしない【採用方向】

- 森・草原・水辺は釣り、生き物取り、住民の散歩や趣味の場として使う。
- 同じエリアでも昼夜・天候・花や木の配置で、見られる生物や行動が変わる。
- 釣り場や生物の場所を探すこと自体が、日常の発見になる。

### 7.2 宇宙生物50種類との連携【既存の生物仕様】

| 環境 | 見られる生物や習性の例 |
|---|---|
| 池・川 | ミズプクなど水辺を好む生物 |
| 花畑 | ハナピカなど花へ集まる生物 |
| 草原の土中 | ホリモグなど地中で暮らす生物 |
| 木々・森 | タネパタ、ハッパリなど |
| 村・住宅の周辺 | 箱や建物を好む種類など |
| 夜の暗がり | ヒカリムシなど発光・夜行性の生物 |
| 鉱山・洞窟 | 岩や結晶の近くを好む生物 |

これらは生息の例であり、特定の種類が必ず単一エリアにしか出現しないという制約ではない。

### 7.3 生物の分布とシード

- ワールドごとに、森林・川・花畑などの環境の広さが変わる。
- その結果、生物の見つかりやすさや出現場所にも差が出る。
- さらに生物の種類ごとの出現傾向に、星固有の違いを付けることも検討する。
- **50種類すべてを各星でどう入手可能にするか、出現確率の細部は未決定**。ただし、本来の生活コンテンツが欠落するマップは作らない。

### 7.4 釣り場

川、池、海岸、地下湖等が釣りの候補。釣れる魚や釣り方は釣りシステム仕様に準拠し、時間帯・天候・釣り場・道具などの違いを活用する。

### 7.5 自然の「お気に入りの場所」【提案】

住民ごとに、川辺のベンチ、静かな森、見晴らしの良い高台などの好みを持たせる。住民同士の思い出によって、お気に入りの場所が変化することもある。プレイヤーは誰がどこによく現れるか観察し、住民辞典や地図に記録できる。

## 8. 山・鉱山のマップ

### 8.1 既存の鉱山方針【既存方針】

- 鉱山は**10階層程度**。
- 深い階層ほど珍しく高価な鉱石が見つかる。
- 硬い鉱石には上位のツルハシが必要。
- 鍛冶屋の宇宙人に鉱石とお金を渡してツルハシを強化してもらう。
- **鉱石は毎日、種類・量・位置がランダムに再出現する**。この星では自然な現象であり、長期的に枯渇しない。

### 8.2 地形と日替わり資源を分離【採用方向】

1. **星のシード**：鉱山入口、山の位置、各階層の基本地形を決める。
2. **日ごとの変化**：岩・鉱石・宝石など、採掘可能資源の出現を更新する。

基本地形とその日の資源配置は異なるレイヤーとして扱う。シード生成のたびに地形が違い、同じ星でも日によって採掘成果が変化する。

### 8.3 移動と住民

- 到達した階層への昇降機による移動は提案段階。
- 山道や鉱山入口には採掘師が訪れることがあり、住民の言動も宇宙語解読の材料になる。
- 地下湖などがある場合は、釣りや生物との連携が可能。
- 複雑な地質解析・永続坑道の掘削建設を鉱山の主役にはしない。

## 9. ロケット不時着地とメインストーリー

### 9.1 始まりから帰還まで使う場所【既存方針】

- 村の近くに、主人公の壊れた宇宙船が残る場所を設ける。
- 主人公はこの星で生活し、お金を稼いで修理部品を購入する。
- 宇宙船は修理の進行に応じて外見が変化する。【提案】
- 修理屋や興味のある住民が現場を訪れることがある。【提案】
- ロケットが修理できれば、**帰還のタイミングはプレイヤーが選ぶ**既存ストーリー案に準拠する。

### 9.2 マップがエンディングの舞台になる【既存ストーリーと連携】

最終章「最後の引っ越し」では、住民たちが普段歩いていた道や村から宇宙船のもとへ集まる。宇宙語は最後まで宇宙語のまま。住み慣れた村の風景が、そのまま別れの演出になる。

## 10. 住民AIとマップの連携

### 10.1 住民は実際に村を歩き、生活する【既存住民生活案】

| 住民の活動 | 利用する場所 |
|---|---|
| 仕事 | 鍛冶屋、種屋、商店、農場等 |
| 買い物 | 主人公の店やほかの店舗 |
| 趣味 | 川、海岸、森、鉱山、花畑等 |
| 交流 | 広場、ベンチ、友人宅、道中 |
| 休息 | 自宅、庭、公園、木陰 |
| 引っ越し | 住宅、玄関、道路、別れの場所 |

- 住民の行動は基本スケジュールに加え、性格・仕事・所持品・気分・約束・短期／中期／長期目標の影響を受ける。
- プレイヤーが見ていないところでも生活が続く。
- 道路や距離、施設配置の違いにより、住民同士の偶然の出会い方が星ごとに変わる。
- 同じ住民でも、その星での住居や知人関係によって生活に違いが生まれる。

### 10.2 会話と行動の整合性【重要】

例えば「明日は釣りに行く」と宇宙語で発言した住民には、実際の予定との対応が必要。予定変更はあり得るが、会話と生活状態を無関係にしない。この一貫性が言語解読の成立条件になる。

### 10.3 住民が実際に買った物を使う【既存住民生活案】

- 花を買ったら飾る、種を買ったら植える、家具を買ったら家に設置する、生物を買ったら飼う、食料を買ったら食事や料理に使うなど。
- その結果、家・庭・住民間の会話や次の行動が変化する。
- プレイヤーは、店で売ったものが村の生活に反映されていることを発見できる。

## 11. 暮らしによるマップの変化

### 11.1 変化するもの【採用方向】

| 変化の範囲 | 例 | 期間のイメージ |
|---|---|---|
| 日常の痕跡 | 釣り具、集まる住民、荷物、会話の場所 | 短時間〜数日 |
| 住居や庭 | 花壇、家具、ペット、飾り、畑 | 長期 |
| 住民構成 | 引っ越し、空き家、新たな入居 | 長期 |
| 商店 | 商品と在庫、売上、来店客 | 日々変化 |
| 農場 | 畑、池、生物の住処、装飾 | プレイヤーの操作に応じて |
| 公共の場所 | ベンチ、桟橋、花壇、伝言広場の充実 | イベントに応じて |
| 宇宙船 | 修理の進行に合わせた外観 | ストーリー進行に応じて |

### 11.2 村の公共施設の発展【提案】

住民たちの希望や共同作業によって、橋や桟橋、ベンチ、公園、花壇、伝言広場などが少しずつ整備されることがある。プレイヤーが資材を手伝う場合もあれば、住民自身が進める場合もある。**公共施設の発展をロケット修理の必須条件にはしない**方向。

### 11.3 出来事が連鎖する例

1. 主人公が商店で青い花を販売する。
2. 花好きの住民が購入し、自宅の庭に植える。
3. 花が増え、ハナピカなど花を好む宇宙生物が集まる。
4. 生物好きの住民がその家を訪れ、花好きの住民と交流する。
5. 二人の関係が変化し、後日の会話や行動にも影響する。
6. プレイヤーは商店履歴、住民の様子、宇宙語の会話から経緯を推理できる。

> この例は設計意図を示すもので、毎回この筋書きになる固定イベントではない。

## 13. タブレットの地図アプリ【追加提案】

主人公が故郷から持ち出したタブレットに、**この星を自分で記録する地図**を追加する案。

### 13.1 記録・表示したい情報

| 情報 | 扱い |
|---|---|
| 地形・道 | 訪れた場所などを記録する案 |
| 建物・施設 | 実際に発見・利用した施設を登録 |
| 自宅・農場・不時着地 | 自分の生活・ストーリーの拠点として記録 |
| 住民の家 | 顔と自分で付けた呼び名を関連付け |
| 自由な地名 | 場所に仮の名前を付け、後から変更可能 |
| 写真 | 撮影した景色をその地点に関連付ける |
| 生物・魚 | 見つけた場所や釣果をメモ |
| 鉱山 | 到達階層、採掘の記録 |
| 宇宙語 | 地名・場所について聞いた言葉を保存 |
| マーカー | お気に入りの場所や調査対象を記録 |

### 13.2 正解を先回りして教えない

- 地形や建物を見つけたという**観測済みの事実**の自動記録は可能。
- しかし、未知の地名・住民の本当の名前・宇宙語の訳を、システムが勝手に記入しない。
- 例えば森に「青い木の森」と自由に仮名を付け、後から宇宙語で呼ばれる地名を推測して書き足せる。
- 地図、宇宙語辞書、住民辞典、生き物図鑑、マネピの音声カードを相互参照できる構想。

### 13.3 別の星の地図

マルチプレイで訪問した星についても、**星ごとに別の地図・自由メモ**を保存する方向。訪問先の宇宙語・住民情報と混同しない。

## 14. マルチプレイと共有世界【既存方針＋提案】

- 別プレイヤーの星へ訪問し、その星のマップと住民の生活を一緒に体験できる。
- 訪問先ではホストの星の地形・施設・住民・宇宙語を使う。
- ホストの農場、商店、鉱山、自然環境など、これまで暮らして変化した状態を訪問者が見ることができる。
- **辞書は自動配布しない**。渡すかどうかは持ち主が決める。
- プレイヤーごとの解読メモ・辞書・住民辞典は独立して扱う。

| 対象 | マルチプレイでの基本方向 |
|---|---|
| 地形・道・建物 | ホストの星の現在状態を共有 |
| 住民・生活 | 同じ住民を見て交流できる |
| 宇宙生物 | 同じフィールドにいる生物を観察・捕獲する構想 |
| 鉱山 | ホスト星の鉱石・採掘状態を共有する構想 |
| 農場 | 協力して作業できる構想 |
| 商店 | ホストの店を訪問・閲覧できる構想 |
| 宇宙語 | ホストの言語が表示される |
| タブレット | 各プレイヤーの辞書・記録は別管理 |

ゲストが農場や家具、道、生物、住民にどこまで変更を加えられるか、進行状況を誰のセーブへ保存するか等は未決定。

## 15. ワールド生成の処理フロー【提案：技術設計】

1. **ワールドシードを確定**し、生成バージョンを記録する。
2. **地形・標高・水系・海岸**を生成する。
3. **森・草原・山・水辺などの自然環境**を配置する。
4. **村の広場・住宅区画**などの候補を決める。
5. **道路・橋・近道**を生成して主要地点をつなぐ。
6. **生活施設・主人公の農場・鉱山入口・不時着地**を配置する。
7. **住宅・庭・外観**を生成する。
8. **初期住民と住宅・仕事・人間関係**を割り当てる。
9. **魚・宇宙生物・鉱山資源等の初期分布**を設定する。
10. **独立した言語系列から宇宙語**を生成し、その星に紐付ける。
11. **移動可能性・施設到達・住民AIの経路**を検証する。
12. **世界を保存して生活開始**。以後は住民とプレイヤーの行動を世界状態へ蓄積する。

生成の正確な順番・データ構造・生成方式は、実装担当による詳細設計で変更できる。ただし、星ごとの違い、言語の一貫性、施設の利用可能性、暮らしの持続という目的は維持する。

## 16. ワールド生成・マップ品質の検証観点【提案】

### 16.1 地理・導線

- 主要施設が欠落せず、主人公と住民が利用できる。
- 川や崖で重要エリアが孤立しない。橋・道・代替経路等が成立する。
- マップがシードごとに十分異なり、家を数件置き換えただけの差に留まらない。
- 村・農場・採集地・鉱山間の移動が、生活ゲームとして無理のないものになっている。
- 住民の経路探索が、生成された地形・橋・室内外の出入口に対応できる。

### 16.2 生活・シミュレーション

- 住民が自宅・仕事場・商店・自然エリアなどを行き来し、生活イベントを実行できる。
- 家・庭・住民構成の変化が、経時的に保存・再現される。
- 住民が購入した商品や飼育生物などが、生活状態と矛盾しない。
- 住民の会話内容と実際の行動・場所が結び付いている。

### 16.3 六つの主要コンテンツ

- どの星でも、釣り・生き物取り・採掘・農業・クエスト・商店が成立する。
- 鉱山は約10階層、深さとツルハシ強化の関係を保つ。
- 鉱石は日替わり再配置で採掘を続けられる。
- 50種類の宇宙生物の習性が、地形・生息環境と整合する。
- 四季を前提とする出現条件や演出が、旧仕様から混入していない。

### 16.4 シード・保存・マルチ

- 同じシード・生成バージョンで初期世界が再現される。
- 生成後のセーブデータでは、地形・宇宙語・住民・生活履歴が矛盾しない。
- マルチ参加者が同じ星のマップと住民を見られる。
- 参加するだけで宇宙語辞書が配布されない。
- 地図に付けた個人メモや推測が他人のデータと混ざらない。

## 17. プレイ体験の例

### 17.1 自分の星では

朝、農場でミズプクが水やりをしている。主人公は作物を商店に並べて村へ出る。広場では鍛冶屋が買い物中の住民と話している。鉱山へ行く道は川沿いの道か森の近道かを選べる。夕方、以前は何もなかった住民の庭に花畑ができていることに気づく。翌日、マネピが残した伝言から、その住民が花を欲しがっていたことを推測する。

### 17.2 友達の星では

自分の星は川のある平地の村だったが、友達の星では海沿いの丘に家が並ぶ。鍛冶屋の場所も、初期住民の顔ぶれも、宇宙語も違う。ホストが作った農場や、引っ越しによって変わった住宅街を見ることができる。ゲストには辞書が自動で渡されないので、ホストに教えてもらうことも、自分で解読することもできる。

## 20. 他仕様書との整合・更新注意

- **宇宙語**：星ごとに単語・語順・文法が変わり、同じ星では一貫している。住民会話・地名・伝言はその星の言語を使用する。
- **タブレット**：主人公が持ち込んだ記録端末。解釈は本人が行い、ゲームが正解を勝手に入力しない。
- **マネピ**：以前の「顔付き文字付箋」案を置き換える。商店・伝言広場・クエストに音声／仕草の伝言として連携する。
- **住民生活**：仕事、買い物、住民同士の関係、家の変化、引っ越しがマップへ反映される。
- **農業**：農場は自由なレイアウトと、宇宙生物によるお手伝い・自動化を重視。旧案の季節作物などは四季なし方針に合わせて別途更新する。
- **生き物取り**：既存の宇宙生物50種類と生息環境の関係を使う。季節による出現制限は前提にしない。
- **鉱山**：旧120階制や複雑な地質シミュレーションを正本に戻さない。約10階層、鍛冶屋の強化、鉱石の日替わり再出現が中心。
- **商店**：店番不要で自動販売。来店者の声・感想はマネピから入手できる。
- **メインストーリー**：不時着地でロケットを修理し、プレイヤーの選んだタイミングで故郷へ帰る。「最後の引っ越し」の舞台に普段の村を使う。

**本仕様の核**：ワールドシードによって毎回異なる星が生まれ、その星に暮らす宇宙人たちの生活によって、時間とともにさらに変化する。知らなかった土地・住民・言葉を少しずつ理解し、自分だけの村の歴史を積み重ねていく。
