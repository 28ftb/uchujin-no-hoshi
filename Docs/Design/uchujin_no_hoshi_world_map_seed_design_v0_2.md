## 1. 先に結論

1. **方式は「見た目は一つにつながった星、内部は地域ごとに分けて扱う」方式（比較の案3）を推す。** 読み込み画面で生活が途切れないことと、住民が同じ道を歩いている感覚を守れるのはこの方式だけ。地上は一枚のまま、鉱山の各階と屋内だけを別エリアにする（今の構成と同じ）。
2. **「道中マップ」は作らない。代わりに、地域と地域のあいだを「つなぎ道」として設計する。** つなぎ道には3種類ある。毎日使う**本道**は短く平らに、寄り道用の**小道**は生物探しのための散歩コースに、**近道**は探索の報酬にする。
3. **星の骨格は「水の旅」で作る。** 山で生まれた水が滝を落ち、湖で休み、村を通って海へ帰る。シードで変わるのは、この水の流れ方・地形の段のつながり方・村が水の流れのどこにあるか。川の上流から下流へ、魚と生き物の顔ぶれが自然に変わる。
4. **高低差は「段」で扱う。** 地形を3〜5段の台地に分け、段の境目を崖・坂・階段・滝・飛び降りられる段差にする。行きは登り坂、帰りは飛び降りて近道。高い所ほど風と霧が多く、星がよく見える。低い所ほど湿って泥が多い。高さの違いがそのまま生息環境の違いになる。
5. **100種の保証は「生息地を先に予約し、足りない分は地形を直す」方式にする。** 木や岩をばらまいた後で数えるのではなく、必要な場所（冷たい湧水の淵、湖の最深部、静かな高台、苔の倒木など）を先に地形へ組み込む。足りなければ、その場で淵を掘る・湧水を置くなどして直す。すべての種に「到達できる場所が何か所あるか」「条件が何日以内に揃うか」を数え、生成のたびに検証する。
6. **毎日の動線には上限を決める。** 自宅〜畑〜自分の店〜広場は走って合計30秒以内、広場から各地域の入口までは走って45秒以内（いずれも【仮数値】）。遠い場所には遠い意味（夜空、静けさ、珍しい魚）を持たせ、帰り道を速くする。
7. **地図の広さは、今の 400m 四方から 800m 四方程度へ広げるのを推す（【仮数値】）。** 魚50種に必要な水域（湖・滝・瀬・淵・沖など）と高低差を、400m に詰め込むと窮屈になる。そのぶん毎日の生活は中心部（半径およそ120m）にまとめる。
8. **【設計決定】（v0.2）魚はモデル制作中の50種を正とし、湖・桟橋・8m以上の滝（滝の裏の洞つき）を全シード必須、高台は「にぎやかな見晴らし台」と「静かな高台」の2種類にする。** 川の区間分け、浅瀬だけ歩ける川、地下湖のタグ、ロードの位置なども解決策を決めた（§2）。

### 2.3 P2・P14・P17：湖を全シード必須にする【設計決定】

**水の種類**：川・池・**湖**・海・地下湖の5種類にする。池は森の中の小さな水（直径12〜40m）、湖は深さと広さのある大きな水、と分ける。

| 最深部 | 深さ8m以上。湖の面積の15%以上が深さ5m以上 | F046、F048、F044 |
| 浅場 | 深さ1.5m以下の岸が湖岸の3割以上 | F010 |
| 中層 | 深さ2〜5mの帯 | F012、F022、F025 |
| 泥底 | 流れ込みのない入り江に1か所以上 | F004 |

| 形 | 場所 | 星の印象 |
|---|---|---|
| 火口湖 | 山の肩・高地（段4） | 高原への遠出。冷たく澄んだ湖 |

**湖の生き物（P14 の解決）**：生き物の場所の種類に「湖」を加える。生き物の出現では**湖の岸を池と同じに扱う**（ミズプク・アワリン・カワハネ・ヌマプニ・コケコロ・ムレピカなど、池を好む種が湖岸にも出る）。生き物のデータ（`CreatureDatabase.cs`）は変えない。

**住民**：湖畔に東屋と小さな桟橋を置き、釣り好き・散歩好きの住民の行き先にする。ただし「静かな岸」には本道を通さない。

**距離**：湖の入口は、ほかの必須地域と同じく広場から本道で45秒以内。

### 2.4 P3：川を区間に分ける【設計決定】

### 2.6 P5：高台を2種類に分ける【設計決定】

| | **にぎやかな見晴らし台** | **静かな高台** |
|---|---|---|
| 施設 | 今の `facility.lookout`（見晴らし台・東屋の整備） | 施設なし |
| 場所 | 段3。広場から本道で20〜30秒 | 段4。広場から60〜90秒。**本道は通さず小道だけ** |
| 離れ方 | — | 家・本道・見晴らし台から80m以上 |
| 住民 | 星の光帯の夜、好奇心のある住民が集まる（今の実装どおり） | 住民の予定では行かない（固有のストーリーで特別に行くのは可） |
| 必ず置く物 | 花・ベンチ・眺め | **木立（5本以上）・開けた草地・小さな池（直径10〜20m）**・下に湖か海が見える眺め |
| 主な生き物 | ハナピカ、フワタネ、ネムリコ、ポカリス | ニジマユ（木立）、ユメボシ・ホシノコ（草地）、ムレピカ（池） |

- **静けさの判定**：半径40m以内に住民・ほかのプレイヤーがいない時、静かな場所を好む種（ユメボシ・ホシノコ）が出やすくなる。星の光帯の夜は住民が見晴らし台に集まるので、静かな高台はかえって静かになる。光帯で出やすくなるホシノコ・ユメボシに、静かな高台で会える。
- **高台の扱い**：生き物の場所の種類では、どちらも「高台（`Hill`）」。静かな高台には「静か」の印を付ける。生き物のデータは変えない。
- 崖の上の見晴らし岩、山頂なども「高台」に含めてよいが、静かな高台の印は上の条件を満たす場所だけに付ける。

### 2.7 P6：深さ0.6mまでの浅瀬だけ歩ける【設計決定】

- 深さ0.6m以下（瀬・飛び石・浅場の岸）は歩いて入れる。それより深い所には入れず、岸で止まる。泳ぎはない。
- 本道は橋で川を渡る。小道は飛び石か浅瀬で渡ってよい。
- 住民も同じ（住民の道路網は橋を通る）。
- 釣りの立ち位置は、岸か浅瀬の中（深さ0.6mまで）。

### 2.8 P7〜P10：検証・天候・データの食い違い【設計決定】

- **P7**：種ごとに、到達できる生息地の数・生息地のある地域の数・会えるまでの日数を検証する（§8.3・§8.4・§12）。
- **P8**：星の気候に、雨・雨上がり・晴れ・強風・霧・無風・荒天・晴れた夜の最低頻度を持たせる（§8.5）。星の性格はその範囲の中で出す。
- **P9**：スナコロ（024）の生息地は、マップの側で「砂浜・川の砂州」として保証する。実装の地形要素（`rock`）を仕様どおり砂（`sand`）にするかは、生き物担当の実装作業として挙げる（§15）。本書では生き物のデータを変えない。
- **P10**：生き物の出現の計算（地形要素が合えば出やすい）は変えない。そのかわり、手掛かりになる物の数を地形の側で保証する。例：箱（ハコネ・ハコバチ）は村に10か所以上、窓（マルマド・ランプル）は家の数だけ、街灯（ランプル・ポカリス）は本道に沿って、屋根（ヤネコロ・ネムリコ）は住宅地に。

### 2.9 P11：桟橋を全シード必須にする【設計決定】

- 海の地域に、桟橋を必ず1本置く。海が村から遠い星でも、海岸の地域の中に置く（広場からの距離は問わない。海岸の入口までは本道で45秒以内）。
- 桟橋の先は**沖**（深さ6m以上【仮数値】）に届く長さにする。F042 ヨルツバサ（沖・桟橋）、F025 リボンウオ（沖）が狙える。
- 沖へのもう一つの立ち位置として、岬か岩の突端を1か所置く。
- 釣り小屋は今の実装どおり村に近い水辺（川か湖）に置く。海が遠い星では、桟橋のそばに小さな休憩所（雨宿り）を置く。

### 2.10 P12：8m以上の滝を必ず1本作る【設計決定】

- 段の境目に川がかかる所に、**高さ8m以上の滝を1本以上**作る（§9.4）。
- 滝つぼは深さ3m以上（F011 ヤマギザ）。滝から下流30mは急流（F023 ハネウオ）。
- **滝の裏の洞**を必ず付ける。小さな別エリア（屋内と同じ扱い）にし、中に暗い淵を置く（F039 シルベフデ）。入口は水しぶきの奥にあり、夜はシルベフデの光が漏れて気づける。
- 小さな滝（2〜4m）は寄り道ポケットとして別に置いてよい（§5.4）。

### 2.11 P13：地下湖のタグを決め直す【設計決定】

地下湖のある階（今の実装の2・4・6・8・10階）はそのままにし、各階の岸に付けるタグを次のようにする。

| 階 | 岸のタグ | 主な魚（原本の生息候補から） |
|---|---|---|
| 2階 | 浅い岸・冷たい | F009 ナガクチ、F020 ホシマメ、F028 ハグルマウオ |
| 4階 | 浅い岸・鉱石の多い岸・冷たい | F009、F020、F028、F032 ジシャクウオ、F041 イワナキ |
| 6階 | 深場・鉱石の多い岸 | F020、F028、F032、F041、F044 ヒヤシウオ |
| 8階 | 深場・鉱石の多い岸・結晶 | F028、F032、F041、F044、F036 クリスタルフィッシュ |
| 10階 | 最深部・深場・結晶 | F036、F041、F044、F049 ガンテイオウ |

- 地下湖の魚は、日付更新で変わる鉱石とは別に、階ごとに固定の地形として扱う（鉱山仕様 §8.2「基本地形と日ごとの資源は別のレイヤー」）。
- どの地下湖にも、地上の魚が混ざらないようにする（原本で「地下湖」とある魚だけ）。

### 2.12 P15・P16：ロードの位置と、施設の離れすぎ【設計決定】

- **P15**：セーブした場所から再開する。地上ならその位置、屋内・鉱山・滝の裏の洞ならその入口の前。保存した場所が使えない時（地形の変化など）は自宅の前。マルチのゲストは、ホストの星の自宅の前ではなく、参加した時の出現位置から。
- **P16**：鍛冶屋・修理屋が広場から離れて建つのは、暮らしの谷の中（広場から本道で25秒以内）に限る。鉱山・不時着地への道沿いの雰囲気は、谷の出口寄りに建てることで出す。

## 3. マップの基本コンセプト

### 3.1 一言で

> **「毎朝同じ道を通っても、毎日ちょっとだけ違うものに出会う星」**
> 生活の中心はこぢんまりと、周りの自然は奥深く。水が山から海へ旅をするように、プレイヤーも星の上流から下流まで、少しずつ知っていく。

### 3.2 面白さの柱【提案】

1. **毎日の道は短く、寄り道は豊かに**：畑・店・広場の往復は気にならない短さにする。一方で、少し外れると必ず何かある。
2. **見えているのに、まだ行けない**：広場から山の上の木立が見える。崖の上で何かが光っている。行き方を探すこと自体が探索になる。
3. **高さは生き物の暮らしの違い**：同じ森でも、谷底の森は湿って苔むし、台地の林は明るく風が通る。いる生き物が違う。
4. **星が変わると暮らし方が変わる**：川の村では毎日川で釣り、湖の村では霧の朝に湖を眺め、岬の村では階段を下りて桟橋へ行く。配置ではなく**生活の形**が変わる。
5. **100種とは「探し方の違い」で出会う**：魚影を見る、音を追う、夜に光を探す、雨を待つ、静かに待つ、岩を叩く。場所の違いだけでなく、探し方の違いで出会いを分ける。
6. **住民と同じ道を歩く**：住民は飾りの道ではなく、プレイヤーと同じ道を通って仕事や趣味に出かける。釣り好きの住民が通う淵は、プレイヤーにとっての手掛かりにもなる。
7. **帰り道はやさしい**：村を地形の真ん中あたりの高さに置き、帰りはほぼ下り坂にする。段差を飛び降りる近道は、どれも村の方へ向かうようにする。

### 3.3 避けること

- 地図を広げただけの空白（何もない草原を歩くだけの30秒）。
- 生物を探すための専用ステージ（住民が来ない場所だけに生き物がいる構造）。
- 鍵のかかった扉（ある道具がないと絶対に行けない場所に、必須の素材を置くこと）。
- 毎日の義務としての長距離移動。

## 4. マップの接続方式の比較

### 4.1 3方式の比較

| 観点 | 案1：すべてつながった連続マップ | 案2：地域マップと道中マップを分ける | 案3：見た目は連続・内部は分割して読み込む |
|---|---|---|---|
| 生活の連続感 | ◎ 途切れない | △ 境目ごとに読み込み。住民が画面の外へ消える | ◎ 途切れない |
| 住民の生活の見え方 | ◎ 遠くを歩く住民が見える | × 村マップ仕様 §2.3 が避けたい「分断」が起きる | ◎ 遠くは軽い表示で見せられる |
| 景色・高低差の見せ方 | ◎ 山頂から村と海が見える | × 隣の地域は「書き割り」になる | ◎ 遠くは低い精細度で見せられる |
| シード差の表現 | ○ 地形の形そのものが変わる | △ 主に「つながり方の図」が変わる | ◎ 形もつながり方も変えられる |
| 道中の面白さ | ○ 作り方しだい | △ 細い一本道になりやすい | ◎ つなぎ道を自由に設計できる |
| 性能（描画・物理） | △ 全部を常に動かすと重い | ◎ 軽い | ○ 近くだけ細かく動かす |
| マルチプレイ（EOS P2P） | ○ ホストが全体を持つ | △ ゲストが別の地域にいるとホストの処理が複雑 | ○ ホストが全体のデータを持ち、表示は各自の近くだけ |
| 実装の手間 | ○ 今の構成の延長 | ○ 作りやすいが、境目の処理が多い | △ 地域ごとの表示切り替えが必要 |
| 生成の検証 | ○ | ○ | ◎ 地域を単位にして検証・修復できる |

### 4.2 おすすめ：案3【推奨】

**見た目は一枚の地上、内部では「地域」を単位に、生成・検証・表示・セーブを扱う。**

- 地上（`overworld`）は一つのエリアのまま。読み込み画面はない。
- 内部では地形を約64m四方のチャンクに分け、プレイヤーの近くだけ細かい物・当たり判定・生き物を動かし、遠くは軽い表示にする（§11.2）。
- 「地域」は**設計上の単位**。生成の手順、生息地の検証、地名、地図アプリ、住民の行き先、セーブの区切りに使う。境目は見えない。
- 別エリアにするのは**鉱山の各階・建物の中・滝の裏の洞**など、地上から切り離して自然な場所だけ。今の `AreaIds`（`mine:N`、`house:*`）の考え方をそのまま使う。

### 4.3 案2を採らない理由と、その良いところの取り込み方

案2の良いところ（地域ごとの密度管理・道中の演出・軽さ）は捨てない。

- **密度管理**：地域ごとに「寄り道ポケット」の数と間隔を決めて配置する（§5.4）。
- **道中の演出**：つなぎ道を「地域の一種」として設計する。山道は山道らしく、浜の岩場道は浜らしく作る。
- **軽さ**：チャンクの切り替えと遠景の軽い表示で得る。

## 5. 星全体の地域構成と道中の役割

### 5.1 全体像：「暮らしの谷」と、その周りの地域【提案】

```
            (静かな高台)          (山・鉱山)
                 \                 /
     (明るい林)---(森の台地)---(渓谷・滝)
          |            \         |
   (花の野)----[ 暮らしの谷：村・自宅・畑・店 ]----(湖)
          |            /         |
    (不時着地)-----(川の下流・湿地)---(海岸・桟橋)

     ---- 本道（毎日・平ら）   …… 小道（寄り道・ぐるりと一周）
```

上の図は**つながり方の例**。実際の位置・数・形はシードで決まる。中心にある「暮らしの谷」から、各地域へ**本道**が放射状に伸び、地域どうしは**小道**で輪のようにつながる。

- 毎日の用事（店・畑・広場）は谷の中で済む。
- 遠出は本道で地域の入口まで行き、帰りは別の小道を通ってぐるりと回れる。行きと帰りで違う景色を通ることになる。
- 輪になっているので行き止まりが少なく、散歩のついでに生き物を探せる。

### 5.2 地域の種類【提案】

**必ずある地域（全シード共通）**

| 地域 | 役割 | 主な遊び | 生息環境の中心 |
|---|---|---|---|
| 暮らしの谷 | 村の中心・住宅・自宅と畑・自分の店 | 商店・交流・農業・クエスト | 屋根・窓・箱・街灯・庭・村の川 |
| 山（鉱山の入口を含む） | 採掘の入口、岩場、山頂 | 採掘・岩場の生き物 | 岩・岩壁・洞穴・結晶の岩場 |
| 渓谷・滝 | 水の旅の始まりの一つ。こだまが響く谷 | 滝つぼの釣り・滝の裏の発見 | 急流・滝つぼ・岩場・苔 |
| 湖 | 水の旅の休憩所。深さのある大きな水 | 湖の釣り・霧の朝・伝説魚 | 浅場・中層・最深部・静かな岸・濁り |
| 森（2種類以上） | 谷底の湿った森／台地の明るい林 | 擬態・音・夜の生き物 | 倒木・苔・キノコ・木・茂み |
| 草原・花の野 | 日当たりと風。昼寝と花 | 花の生き物・風の生き物 | 花・草・日なた |
| 海岸 | 水の旅の終わり。砂浜・岩場・桟橋 | 海釣り・浜の生き物 | 砂・岩・波・沖 |
| 高台（2か所以上） | にぎやかな見晴らし台と、静かな高台 | 星空・夜の生き物・眺め | 高台の木立・夜の静けさ |
| 不時着地 | ロケットの修理作業場 | メインストーリー | （開けた草地。農場と同じく誘致の余地） |

**シードによって加わる地域（0〜4か所）**

湿地（泥と葦）、段々の果樹林、岬、砂州、高原の池、二つ目の滝、苔の古い森、結晶の岩場、湧き水の谷、川の中州など。どれが出るかで星の「名物」が変わる。

### 5.3 つなぎ道（道中）の3種類【推奨】

| 種類 | 使う人 | 長さの目安【仮数値】 | 作り方 |
|---|---|---|---|
| **本道** | 住民・プレイヤーが毎日使う | 広場から各地域の入口まで走って45秒以内（約360m以内） | 幅が広く、坂はゆるく、橋がある。住民が歩ける。雨宿りできる東屋を一定の間隔で置く |
| **小道** | プレイヤー（住民も趣味で通る） | 地域と地域のあいだを走って40〜80秒 | 曲がりくねり、高さが変わる。**寄り道ポケット**を2〜4か所置く。ぐるりと輪になるように結ぶ |
| **近道** | プレイヤー | 数秒〜十数秒 | 飛び降りられる段差、飛び石、はしご、つり橋、滝の裏の通り抜け。**見つけたら使える**か、住民の整備で開通する |

「道中」は細い一本道ではなく、**小道そのものが寄り道の場所**になる。本道は住民の生活のため、小道はプレイヤーの探索のため、と役割を分けることで、毎日の移動が苦痛にならず、寄り道も楽しくなる。

### 5.4 寄り道ポケット【提案】

小道の途中に置く、10〜20m ほどの小さな場所。**どれも何かの生息地を兼ねる。**

| ポケット | 見た目 | 主に出会えるもの |
|---|---|---|
| 湧き水の窪地 | 冷たい水が湧く小さな池 | F008 シモマダラ、ツユツユ、コケコロ |
| 苔の倒木広場 | 倒木と苔とキノコ | モリマル、トビカサ、ツチポン、エダミミ |
| 小さな滝と淵 | 2〜4m の滝と深い淵 | F011 ヤマギザ、F035 カサビレ、イシペタ |
| 崖の上の見晴らし岩 | 段の縁の岩場。下の水面に魚影が見える | ポカリス、ネムリコ、クルマリ（眺めの手掛かり） |
| 石積みの跡 | 誰かが積んだ小石 | ツミツミ、ポケットン |
| 花の段々 | 段差に沿って咲く花 | ハナピカ、フワタネ、イロポポ |
| 岩の割れ目の洞穴 | 崖の小さな洞 | カベピタ、コダマル（地上） |
| 夜光キノコの輪 | 夜だけ光る輪 | ヒカリムシ、スミカゲ（明かりの縁） |
| 泥の岸 | 葦と泥 | ヌマプニ、ホリモグ、F004 ヒゲタマ |
| 飛び石の浅瀬 | 川を渡れる浅い瀬 | F003 チョロスジ、カワハネ、アワリン |

ポケットは**走って20〜30秒に1つ**の間隔を目安にする【仮数値】。何もない区間が長く続かないようにする。

### 5.5 移動時間の予算【仮数値】

ゲーム内1日＝現実30分【既存方針の仮数値】、プレイヤーの走る速さ 8m/秒【現行実装】として計算する。

| 区間 | 上限（走って） | ゲーム内時間の目安 |
|---|---|---|
| 自宅 → 畑 | 5秒 | すぐ |
| 自宅 → 自分の店 → 広場 | 合計30秒 | 約25分 |
| 広場 → 村の川の釣り場 | 15秒 | 約12分 |
| 広場 → 各地域の入口（本道） | 45秒 | 約35分 |
| 広場 → 一番遠い場所（近道あり） | 75秒 | 約1時間 |
| 広場 → 一番遠い場所（近道なし・最短経路） | 120秒 | 約1.5時間 |

遠い場所は、行けば半日がかりの「遠出」になる。それでよい（ゲームバランス仕様 §14.3「遠くの森や海岸は探検としての距離の意味を持ってよい」）。そのかわり、**遠い場所には遠い理由**を持たせる（夜空・静けさ・伝説魚・名物の地形）。

## 6. シードによって何を変え、何を固定するか

### 6.1 三つの層【推奨】

| 層 | 内容 | 方針 |
|---|---|---|
| **固定する約束** | 遊びと生活が成り立つための条件 | 全シードで必ず守る |
| **範囲の中で変えるもの** | 大きさ・距離・数・頻度 | 上限と下限の間で変える |
| **大きく変えるもの** | 星の性格・暮らしの形 | 積極的に違いを出す |

### 6.2 固定する約束（全シード共通）【推奨。うち湖・桟橋・滝・高台は設計決定】

- 必須施設がすべてあり、主人公も住民も道で行ける（村マップ仕様 §16.1【既存方針】）。
- 必須の地域（§5.2）がすべてあり、どれも**最初の日から**到達できる（鉱山の深い階を除く）。
- 湖・川・森の池・海岸（砂浜・岩場・桟橋）の水域がすべてある。**湖は §2.3 の最低条件、桟橋は沖まで届く長さ（§2.9）、滝は8m以上で滝の裏の洞つき（§2.10）**【設計決定】。
- **にぎやかな見晴らし台と静かな高台が1つずつ以上ある**（§2.6）【設計決定】。
- 魚50種・生物50種の全種に、到達できる生息地がある（§8）。
- 鉱山は約10階層、入口は山の地域に1か所【既存方針】。
- 毎日の動線が §5.5 の上限に収まる。
- どこへ飛び降りても、必ず村へ歩いて戻れる（閉じ込められる場所がない）。
- 帰還に必要な修理素材が、どのシードでも手に入る（ロケット修理仕様 §15.1【既存方針】）。

### 6.3 範囲の中で変えるもの【提案・仮数値】

| 項目 | 範囲の例 |
|---|---|
| 可動域の大きさ | 720〜880m 四方（外周の形が変わる） |
| 段（台地）の数 | 3〜5段 |
| 山の高さ | 60〜120m |
| 滝の数・高さ | 1〜3本、4〜25m |
| 湖の大きさ・最深部 | 直径 90〜220m、深さ 8〜20m |
| 森の池の数 | 2〜5か所 |

### 6.4 大きく変えるもの【推奨】

| 変えるもの | 例 | 生活への影響 |
|---|---|---|
| **村が水の旅のどこにあるか** | 上流の渓谷の村／川をまたぐ中流の村／湖畔の村／河口の村 | 毎日釣る魚、住民の趣味の行き先、橋の数 |
| **水の流れ方** | 山→滝→湖→村→海／山→村→湖→海／二つの山から川が合流／湖から川が二手に分かれる | 魚の分布の順番、湿地の位置 |
| **山の形** | 一つの大きな山／尾根が連なる／二つの峰／くぼんだ火口（火口湖） | 鉱山への道、こだまの谷、静かな高台の位置 |
| **海との関係** | 村から見える近い海／尾根の向こうの遠い海／崖の下の入り江／遠浅の長い浜 | 海釣りが日常か遠出か |
| **段の性格** | 平らな谷に段が1つ／段々畑のような斜面の村／崖に囲まれた盆地 | 毎日の階段、近道の多さ、景色 |
| **日当たり** | 星ごとの太陽の通り道で、日なたの斜面と日陰の斜面が決まる | 花畑・昼寝の場所と、苔・影の森の位置 |
| **名物の地域** | 湿地・結晶の岩場・砂州・高原の池など | その星で会いやすい生き物（どの種も会えなくはならない） |
| **地名** | 地形の意味から宇宙語で作る（§9.10） | 地名が宇宙語の手掛かりになる |

### 6.5 星の差の「出しすぎ」を防ぐ

- 全100種は**全シードで会える**。変わるのは「会いやすさ」と「出会う場所」。星ごとの名物（その星だけ会いやすい種）を2〜5種作るのはよいが、会えない種は作らない。
- 生活の基本（店・広場・畑の近さ）は星によって不公平にしない。
- 地形のせいで修理が事実上できない星を作らない（ロケット修理仕様 §15.1）。

## 7. 高低差を生かした探索

### 7.1 「段」で考える【推奨】

地形を自由な凸凹ではなく、**3〜5段の台地**として作る。斜め見下ろしのカメラでも高さが読み取りやすく、崖・坂・滝が意味を持つ。

| 段 | 標高の目安【仮数値】 | 主な場所 | 環境の傾向 |
|---|---|---|---|
| 0：海と浜 | 0〜4m | 砂浜・岩場・河口・桟橋 | 風が強い、塩、波 |
| 1：低地 | 4〜12m | 川の下流・湿地・不時着地・畑の候補 | 湿る、泥、葦、霧が溜まりやすい |
| 2：暮らしの段 | 12〜24m | 村・住宅地・自宅（多くの星） | 平ら、日当たり、人の気配 |
| 3：台地 | 24〜45m | 森の台地・花の野・湖（多くの星） | 明るい林、風が通る |
| 4：高地 | 45m〜 | 山・尾根・静かな高台・高原の池 | 風と霧、涼しい、星がよく見える |

村は**段2**に置くことが多い。上へも下へも行けるうえ、帰り道が下り坂になりやすい。

### 7.2 段の境目のつくり【推奨】

| 境目 | 登れるか | 降りられるか | 使い方 |
|---|---|---|---|
| ゆるい坂 | ○ | ○ | 本道。住民も通る |
| 階段 | ○ | ○ | 村の中・段々の住宅地 |
| 崖 | × | ×（高すぎる） | 景色と区切り。崖の面にカベピタ・洞穴 |
| 飛び降りられる段差（4m以下【仮数値】） | × | ○（一方通行） | 帰りの近道。村の方へ向ける |
| はしご・つる | ○ | ○ | 住民の整備で付く近道（プレイヤー専用） |
| 滝 | × | × | 段の境目に水が落ちる場所。滝つぼと滝の裏 |
| 浅い瀬・飛び石（深さ0.6m以下） | 川を渡れる | — | 川を渡る近道。浅い所だけ歩ける【設計決定 §2.7】 |
| 淵・本流の深い所（深さ0.6m超） | 入れない | — | 橋が必要。川が地形として働く【設計決定 §2.7】 |

「歩いて川を渡れない」ことは不便に見えるが、**橋と飛び石があるから川辺に人が集まる**（村マップ仕様 §3.3「橋周辺が人の集まる場所になる」）。

### 7.3 高さが生き物と魚の違いになる【提案】

- **水温**：高い所の湧き水と滝つぼは冷たい → F008 シモマダラ、F044 ヒヤシウオ（湖の深場）。
- **流れ**：段の境目の近くは急流、平らな所は淵とよどみ → F023 ハネウオ・F003 チョロスジ と F007 ペラオビ・F027 サカサウオ。
- **風**：高地と海岸は風が強い → フワタネ、タネパタ、ナミパタ、F038 カゼウケ。盆地の湖は風が弱い → F046 カガミヌシ（無風）。
- **霧**：低地の湿地と盆地の湖に朝霧が溜まる → F040 キリガクレ、モリマル、トビカサ、マルマド。
- **日当たり**：太陽を向いた斜面は花と昼寝 → ハナピカ、ネムリコ、ポカリス。陰の斜面は苔と影 → モリマル、スミカゲ。
- **夜空**：高い所ほど星がよく見える → ユメボシ、ホシノコ、F050 ソラワタリ（湖・海の広い水面）。

天候そのものは星全体で一つ（時間天候仕様 §5）。地域ごとには「霧が出やすい」「風が強まる」程度の**補正だけ**を持たせる（時間天候仕様 §13「地形との関係」の提案に沿う。複雑な気象計算はしない）。

### 7.4 高台を二つに分ける【設計決定】

詳しい条件は §2.6。要点だけ書く。

| 高台 | 場所 | 誰がいるか | 何が起きるか |
|---|---|---|---|
| **にぎやかな見晴らし台** | 段3。村から本道で20〜30秒 | 星の光帯の夜に住民が集まる（`Residents/README.md` の実装どおり） | 住民の会話・イベント。ハナピカ・フワタネ・ネムリコ |
| **静かな高台** | 段4。小道の先（村から60〜90秒）。本道は通らない。家・本道・見晴らし台から80m以上 | ほとんど誰も来ない | ニジマユ（木立）、ユメボシ・ホシノコ（草地）、ムレピカ（小さな池）。下に湖か海が見える |

「生き物たちが静かに集まる場所」（ホシノコ）を、**住民が集まる丘とは別の場所**として地形に組み込む。星の光帯の夜は住民が見晴らし台に集まるので、静かな高台はかえって静かになる。

### 7.5 「見えているのに行けない」の作り方【提案】

- 広場から、段3・段4の目立つもの（大きな木、滝、光る岩）が見えるようにする。
- それらへの道は、まっすぐ行けば崖、回り込めば小道、という形にする。
- 崖の上から下を見ると、淵の魚影や、岩場で眠るイワネムが見える。**上から見て見つけ、下へ降りて捕まえる**流れを作る。
- 滝の裏には洞がある（F039 シルベフデの「滝の裏の暗い淵」）。最初は気づかず、水しぶきの奥の暗がりや、夜に漏れる光（シルベフデの光の軌跡）で気づく。

## 8. 魚50種・宇宙生物50種の生息地の保証

### 8.1 考え方：「先に生息地を予約し、足りなければ地形を直す」【推奨】

1. 各種の生息条件を、地形の言葉（**生息環境タグ**）に置き換える。
2. 地形を作る途中で、必要な生息環境を**予約**する（例：冷たい湧水の淵を2か所、湖の最深部を1か所）。
3. 自然物を置いた後、種ごとに「到達できる生息地が何か所あるか」「条件が揃うまで何日かかりそうか」を数える。
4. 足りなければ**地形を直す操作**（淵を掘る・湧水を置く・倒木を置くなど）を行う。それでも足りなければ、別の乱数で作り直す（今の実装と同じく決定的に）。

**種のデータが生息条件を持ち、地形生成がそれを読む**形にする。種を足したり条件を変えたりすると、生成と検証が自動で追従する。

### 8.7 プレイヤーの行動で変わる生息地【提案】

- **農場と庭**：池・花畑・果樹・箱・灯り・岩を置くと生き物が来る（生物仕様 §9【既存の提案】、実装済みの誘致）。農場の周りの拡張用の余地（実装では 12m）は、この誘致のための「自分で作る生息地」として扱う。
- **住民の暮らし**：花好きの住民が庭に花を植えるとハナピカが来る（村マップ仕様 §11.3）。商店で売った物が生息地を増やす。
- **踏み跡**：よく通る所は草が土の道になる（実装済み）。人がよく通る所は、隠れる生き物が少し減り、ハコバチやモフピのような人なれした生き物がよく来る、という差を付ける案。
- **鉱山**：掘るとホコリフが舞う、岩を叩くとイワネムが起きる（実装済み）。

## 9. シード生成アルゴリズムの基本設計

### 9.1 全体の流れ【提案】

今の `WorldGenerator`（生成バージョン1）を残したまま、**生成バージョン2**として作る。生成済みの星の地形は変えない（村マップ仕様 §1.3）。乱数は工程ごとに `SeededRandom.For(seed, "world.gen2.<工程>")` で分け、ある工程を直しても他の工程の結果が変わらないようにする（村マップ仕様 §1.4、今の実装の考え方と同じ）。

```
 1. 星の気質        → 起伏・湿り気・風・日当たり・気候の傾向
 2. 地域グラフ      → 地域の種類・位置・段・つながり
 3. 水の旅          → 水源・滝・湖・川・河口の流れ
 4. 高さの地形      → 段の台地・崖・坂・谷・川の掘り込み
 5. 水の詳しい形    → 川の区間（瀬・淵…）・湖底・海底・池
 6. 生息地の予約    → 100種に必要な場所を先に確保
 7. 村の配置        → 広場・施設・住宅区画・自宅と畑・不時着地
 8. 道              → 本道・小道（輪）・近道・橋・飛び石
 9. 植生と小物      → 森・草原・花・岩・倒木・寄り道ポケット
10. 地名            → 地形の意味から宇宙語の地名
11. 検証と修復      → 到達・生活動線・100種の生息・カメラ
12. 初期住民        → 家・仕事・お気に入りの場所
13. 焼き込み保存    → 骨格データをセーブへ
```

### 9.2 工程1：星の気質

いくつかの値の組み合わせとして決める（固定の型から選ばない：村マップ仕様 §1.2）。

| 値 | 範囲 | 効果 |
|---|---|---|
| 起伏 | 0〜1 | 段の数・崖の高さ・山の高さ |
| 湿り気 | 0〜1 | 森の広さ・湿地・池の数・雨と霧の頻度 |
| 風 | 0〜1 | 草原の広さ・強風の頻度・木の傾き |
| 太陽の通り道 | 角度 | 日なたの斜面と日陰の斜面 |
| 海の近さ | 0〜1 | 海が村から見えるか、尾根の向こうか |
| 夜空の豊かさ | 0〜1 | 晴れた夜・星の光帯の頻度 |

### 9.3 工程2：地域グラフ

1. 可動域（720〜880m 四方）の中に、まず**海の側**を決める（1辺、2辺の角、入り江など）。
2. 海から遠い側に**山**を置く。山の形（一つ・尾根・二つの峰・火口）を決める。
3. 山と海のあいだに**暮らしの谷**を置く。村が水の旅のどこにあるか（上流・中流・湖畔・河口）を決める。
4. 残りの必須地域（湖・森2種・花の野・渓谷と滝・高台2つ・不時着地）を、地形の理屈に合う位置へ置く。
   - 湖は「山の肩の火口湖」「谷を塞いだ湖」「盆地の湖」「低地の沼の湖」のどれか。
   - 静かな高台は村から最も遠い高地。にぎやかな見晴らし台は村の近くの段3。
   - 花の野は日なたの斜面。湿った森は日陰の谷底。
5. 星の気質に応じて任意の地域を0〜4か所足す。
6. 地域どうしを**つなぎ道**で結ぶ。暮らしの谷から各地域へ本道、隣り合う地域どうしを小道で結び、輪を1〜3周作る。

地域はグラフの点として持ち、位置・段（高さ）・種類・大きさを持つ。後の工程はすべてこのグラフを見て作るので、**地形の「意味」が先に決まり、形が後から付く**。

### 9.4 工程3：水の旅

1. 山の高い所に**水源**（湧水）を1〜3か所置く。
2. 地域グラフの段の高低に沿って、水源から海までの**流れの道筋**を決める。湖を通るか、村を通るか、どこで合流・分岐するかはここで決まる。
3. 道筋が段の境目を越える所を**滝**にする。少なくとも1本は高さ8m以上【仮数値】にし、滝つぼと**滝の裏の洞**を付ける。
4. 湖では流れ込む口（濁り）と流れ出る口を決める。
5. 海へ出る所を**河口**にする。

### 9.5 工程4：高さの地形

- 各地域の段の高さを基準に、台地を滑らかにつなぐ。段の境目のうち、本道が通る所は坂にし、それ以外は崖・飛び降りられる段差・滝にする。
- 川の道筋に沿って谷を掘る。勾配の急な所は狭く深い渓谷、平らな所は広い谷にする。
- 細かい凹凸は雑音（今の `WorldNoise`）で付けるが、**段の境目と川の位置は雑音で動かさない**。

### 9.6 工程5：水の詳しい形

- 川の中心線の勾配から流れの速さを計算し、区間（急流・早瀬・瀬・淵・よどみ・水草帯）を決める。曲がりの外側を淵、内側をよどみにする。
- 湖底の深さの地図を作り、浅場・中層・最深部を区分する。最深部は8m以上【仮数値】。
- 海底の深さから砂浜・海底近く・深場・沖を区分する。桟橋は沖へ届く長さにする。
- 森の池を2〜5か所、湧水・泥底・濁りを振り分けて置く。

### 9.7 工程6：生息地の予約

§8 の生息条件を「予約リスト」にして、地形の中に場所を確保する。

| 予約の例 | 置き方 | 足りない時に地形を直す操作 |
|---|---|---|
| 冷たい湧水の淵 ×2 | 川の曲がりで崖の下、または森の池 | 淵を掘る＋湧水を置く |
| 湖の静かな岸 ×2 | 本道・家から40m以上離れた湖岸 | 本道の位置をずらす |
| 静かな高台の木立 | 静かな高台に木を5本以上 | 木立を植える |
| 高台の池 | 静かな高台か段4 | 小さな池を掘る |
| 苔の倒木広場 ×3 | 湿った森 | 倒木・苔・キノコを置く |
| 砂州・砂浜 | 海と川の河口 | 砂の岸を作る |
| 崖の洞穴 ×3 | 山の段の境目 | 崖に洞穴を付ける |
| こだまの渓谷 | 山の近くの深い谷 | 谷を狭める |
| 野生の果樹 ×4 | 明るい林・段々の果樹林 | 果樹を植える |
| 泥の岸・湿地 | 低地の池・川の下流 | 泥の岸を作る |

予約した場所は、後の工程（村の配置・道・植生）で**壊さない**。

### 9.8 工程7：村の配置

- 暮らしの段の中で、平らで広い所に広場を置く（今の実装の広場の作り方を引き継ぐ）。
- 広場のまわりに主人公の商店・伝言広場・種屋・雑貨屋・家具職人・共用調理場・修理屋・鍛冶屋を置く（今の実装と同じ施設。鍛冶屋は鉱山への本道沿い、修理屋は不時着地への道沿いに建つこともある）。
- 住宅区画は地形に合わせて種類を変える：**段々の家・川沿いの家・森の縁の家・浜の家・丘の家**。どの区画も平らな敷地・道に面した玄関・広場までの道のり上限を守る。
- 自宅と畑は広場から走って20秒以内の平らな所。畑の周りの拡張用の余地は今の実装どおり確保する。
- 不時着地は村から本道で行ける開けた場所。村からロケットが見えると、修理の進み具合が毎日目に入る。

### 9.9 工程8：道

- **本道**：今の `RoadPlanner`（勾配・水・建物を避ける A*）を拡張し、坂の上限を住民が歩ける角度にする。川は橋で渡る。雨宿りの東屋を約120mごとに置く【仮数値】。
- **小道**：地域どうしを結ぶ。わざと少し曲がりくねらせ、寄り道ポケット（§5.4）を通るようにする。輪になるように結ぶ。
- **近道**：段の境目に飛び降りられる段差を置く（村の方向へ）。飛び石の浅瀬、滝の裏の通り抜け、はしごの候補地（住民の整備で付く）を決める。

### 9.10 工程10：地名【提案】

地域の名前を、その場所の特徴の意味から宇宙語で作る（例：「水」＋「落ちる」＋「森」）。看板・住民の会話・地図アプリで同じ地名が使われる（今の実装は施設の看板を宇宙語で表示している）。地名を見て「この語は『滝』かもしれない」と推理でき、地名そのものが宇宙語の手掛かりになる。正しい訳は表示しない【既存方針】。

### 9.11 工程11：検証と修復

§12 の検証を行い、問題があれば修復し、それでも駄目なら別の乱数系列で作り直す（今の実装と同じく決定的に。上限回数あり）。作り直しが一定の割合を超えるシードの傾向は、自動テストで見つけて生成の側を直す。

### 9.12 工程13：焼き込み保存【推奨】

星を作った時に、**骨格データ（高さ・水・道・建物・生息地点の位置）を圧縮してセーブに保存する**。

- 生成コードを後から直しても、既存の星の地形が変わらない（村マップ仕様 §1.3）。古い生成バージョンのコードをずっと残しておく必要がない。
- マルチプレイで、ゲストのゲームの版がホストと違っても、ホストから骨格データを送れば同じ星になる。
- 大きさの見積もり：800m 四方・2m 間隔の高さで約16万点。圧縮して1〜2MB 程度【見積もり】。

## 10. 住民の移動と日常生活の快適さ

### 10.1 住民が困らないための約束【推奨】

| 約束 | 内容 |
|---|---|
| 道でつながる | すべての家・職場・店・広場・住民の趣味の行き先が本道か小道でつながる |
| 住民は、はしごを使わない | はしご・飛び降りる段差はプレイヤー専用。住民の経路は坂・階段・橋だけ |
| 歩ける坂 | 本道の坂は住民の歩き方で不自然にならない角度まで |
| 雨宿り | 本道には一定の間隔で軒下・東屋がある（住民生活仕様・時間天候仕様の「雨宿りで会話」が地形によらず起きる） |
| 仕事場まで近い | 住民の家から職場まで、住民の歩く速さ（実装 2.1m/秒）でゲーム内1時間以内 |
| 趣味の行き先 | 釣り好きには近い釣り場、星好きには見晴らし台を、それぞれ一定の道のり以内に用意する |
| 玄関の前 | 家の玄関の前に平らな場所があり、道から入れる |

### 10.2 住民の移動の仕組み【推奨】

- **長い移動は道路網で**：今の実装どおり、住民は道路網（`FindPath`）で歩く。決定的で軽く、マルチの同期とも相性が良い。
- **近くでの動きは局所的に**：広場・店の中・釣り場の立ち位置・家具のまわりなど、道路網では表せない所だけ、局所の歩ける面（NavMesh など、§11.4）で動く。
- **見ていない住民も同じ速さで動く**：プレイヤーから遠い住民は、見た目を出さずに道のりと時間だけで位置を進める。「明日湖へ行く」と話した住民が、本当にその時刻に湖にいることを守る（村マップ仕様 §10.2）。
- **遠出は予定に組み込む**：遠い地域への趣味は「半日の遠出」として予定を立てる。行き帰りの時間を見込み、会話の内容と合わせる。

### 10.3 主人公の毎日を快適にする【提案】

- 自分の店は広場に面して置く（住民がよく通る。売れ行きを見に行くのも楽）。
- 広場から見えるランドマーク（山・滝・大きな木・海）で、どこにいても方角が分かる。
- 本道の分かれ道に宇宙語の道標を置く（今の実装の広場の道標を本道全体へ）。
- 段差を飛び降りる近道は、どれも村の方へ。遠出の帰りが速い。
- 夜遅くの遠出でも、帰り道の本道には灯りがある（ランプルの生息地も兼ねる）。
- **乗り物は序盤に入れない**。中盤以降に、住民の整備（公共施設の発展）で**渡し舟・トロッコ**のような住民も使う乗り物を2〜3路線だけ作る案【提案】。歩く楽しさを壊さない数にとどめる。

### 10.4 村の変化とマップ

今の実装の「公共施設の整備」（広場の花壇・橋の灯り・桟橋の延長・池の木の桟橋・森の休憩所など）に、**近道の開通**（はしご・つり橋・飛び石）を加える案。住民が整備した近道を、住民の暮らしと一緒に使えるようになる。ロケット修理の必須条件にはしない【既存方針】。

## 11. Unityでの実装方針と課題

### 11.1 地形

- **Unity の Terrain ではなく、今の自作のチャンク地形（`TerrainBuilder` のメッシュ＋MeshCollider）を拡張する**のを推す。崖の垂直な面・洞穴・滝の裏のくぼみは、高さだけの Terrain では作りにくい。
- 2m 間隔の高さでは崖が丸くなるので、段の境目に沿って**崖のメッシュ**（岩の壁）を別に作り、当たり判定も付ける。
- 水は水域ごとのメッシュ。川は中心線から流れの向きを付け、湖と海は深さで色を変える。滝はメッシュと粒子。

### 11.2 表示の切り替え（案3の中身）

- 地形を約64m四方のチャンクに分ける（800m 四方で約13×13）。
- プレイヤーの近くは細かい物・当たり判定・生き物、中くらいの距離は木と岩だけ、遠くは低い精細度の地形だけ。
- **遠景は消さない**。山頂から村と海が見えることが、この方式を選ぶ一番の理由。
- 木・草・岩はチャンクごとにまとめて描く（今の `MeshBatcher` の考え方。GPU インスタンシングも候補）。
- マルチでは、表示の切り替えは各端末が自分の近くで行い、ホストは星全体のデータを持つ。生き物の出現は今の実装どおり各プレイヤーのまわりで行う。

### 11.3 カメラ

- 既定は斜め見下ろし（今の実装）。高低差が大きくなるので、
  - 崖や家がプレイヤーを隠したら、その物を半透明にする。
  - 段の縁ではカメラを少し引く、見晴らしの場所では大きく引く。
  - 狭い渓谷・滝の裏など、カメラが入れない所は場所ごとのカメラ設定を置く。
- 高さが読み取れるように、崖の影を落とす（今は地形が影を落とさない設定）。段ごとに地面の色をわずかに変える案も。

### 11.4 移動の経路（NavMesh）

- 住民の長い移動は道路網（今の実装）を続ける。
- 局所の動きに NavMesh を使う場合は、Unity の AI Navigation パッケージ（`com.unity.ai.navigation`）を入れ、生成後にチャンクごとに実行時に焼く。**このパッケージは今のプロジェクトに入っていない**。入れるかどうかは試作で決める（§14 U10）。
- 生き物は高さの地形の上を簡単な操向で動く（今の実装）。

### 11.5 エリアとシーン

- 今の構成（空のシーンから `GameBootstrap` がすべてを作る）を続ける。地上は `overworld` 一つ、鉱山の各階・屋内・滝の裏の洞を別エリアにする。
- 追加のシーンファイルは使わない。

### 11.6 セーブ

| 保存するもの | 方式 |
|---|---|
| シード・生成バージョン | 今の実装どおり |
| 骨格データ | 星を作った時に焼き込み、圧縮して保存（§9.12） |
| 変化した分 | 踏み跡・公共施設・農場・置いた物・開通した近道など。地域ごとに分けて保存 |
| 個人の記録 | 地図・ピン・地名のメモは星ごと・個人ごと（今の実装の `PlayerPlanetKnowledge`） |

### 11.7 シードの再現性

- 乱数は `SeededRandom` / `StableHash` だけ（`UnityEngine.Random` 禁止【AGENTS.md】）。
- 辞書の並び順や並列処理の順番に結果が左右されないようにする。並列で計算する場合は、各マスの結果がそのマスだけで決まる形にする。
- 生成は Unity の外（コンソール）でも動く純粋な C# にする（今の生成と同じ）。自動テストで大量のシードを回すため。

### 11.8 課題とリスク

| 課題 | リスク | 対策 |
|---|---|---|
| 生成時間 | 今は 400m で 0.15〜0.4秒（コンソール）。面積4倍と工程の追加で増える | 新しい星を作る時だけなので、数秒までは許容。進み具合を表示する |
| 描画負荷 | 遠景・木・水面・街灯の点光源 | チャンクの切り替え、まとめ描き、灯りの数の上限 |
| 崖とカメラ | 見えない場所ができる | カメラの自動調整と半透明化、自動テスト（§12.4） |
| 住民の数と遠出 | 遠い所へ行く住民の処理 | 見ていない住民は道のりと時間だけで動かす |
| 魚の実装の置き換え | 41種から50種へ。修理用の魚の ID も変わる | 原本をリポジトリに取り込み、移行の作業を別に立てる |
| 既存のセーブ | 生成バージョン1の星 | 版1の生成は残す。新しい星から版2 |

## 12. 生成失敗や到達不能を防ぐ自動テスト

### 12.1 テストの3段階

| 段階 | どこで | 何を | 量 |
|---|---|---|---|
| A. 生成の検証 | 星を作る時、毎回 | §12.2 の項目。駄目なら修復・作り直し | 1シード |
| B. 大量シードの検査 | コンソール（Unity なし） | 多数のシードを作って集計・報告 | 1万シード（夜間）、500シード（毎回のコード変更時） |
| C. 実機での検査 | Unity のバッチモード | 実際に地形を作り、歩かせ、撮影 | 20シード |

### 12.2 生成のたびに検証する項目

**到達**

- プレイヤーの歩ける面（坂の上限・段差・水深）を細かい格子で作り、**一方通行の段差を含む向きのある図**にする。
- 必須施設・必須地域・すべての生息地の予約地点が、広場から最初の日に行けるか。
- **行ける所からは必ず広場へ戻れるか**（一方通行の段差で閉じ込められないか）。
- 住民の道路網で、すべての家・職場・趣味の行き先がつながるか（はしごを使わずに）。

**生活の動線**

- §5.5 の移動時間の上限に収まるか。
- 本道の坂の角度、橋の有無、雨宿りの間隔。
- 住宅区画の数と、どの区画にも玄関前の平らな場所があるか。
- 自宅・畑・不時着地が平らか。

**100種の生息**

- 種ごとに、到達できる生息地の数と、生息地のある地域の数が保証の最低数以上か（§8.3・§8.4）。
- 修理用の魚の保証（§8.3）。
- 静かな場所の保証（本道・家からの距離）。
- 星の気候が §8.5 の最低頻度を満たすか。

**v0.2 で決めた地形の条件**

- 湖が §2.3 の最低条件をすべて満たすか（大きさ・最深部・浅場・中層・泥底・砂泥底・濁り・静かな岸・霧・風・最深部へ届く立ち位置）。
- 川の区間（瀬・淵・よどみ・水草帯・岩場）がそれぞれ2か所以上あるか（§2.4）。
- 桟橋があり、先が沖（深さ6m以上）に届くか。沖へのもう一つの立ち位置があるか（§2.9）。
- 8m以上の滝があり、滝つぼ（深さ3m以上）・急流・滝の裏の洞の入口があるか（§2.10）。
- にぎやかな見晴らし台と静かな高台があり、静かな高台が家・本道・見晴らし台から80m以上離れ、木立・草地・小さな池があるか（§2.6）。
- 深さ0.6mを超える水に入れないこと、本道がすべて橋で川を渡ることを、歩ける面の図で確かめる（§2.7）。
- 鍛冶屋・修理屋が広場から本道で25秒以内か（§2.12）。

**見た目**

- 地域の数・段の数・滝の数などが範囲の中か。
- 寄り道ポケットの間隔。

### 12.3 大量シードの検査（段階B）

コンソールで、多くのシードを作って次を集計し、結果を表と地図の画像で出す。

| 集計 | 合格の目安【仮数値】 |
|---|---|
| 生成に失敗したシード | 0 |
| 作り直しが必要だったシード | 15%以下 |
| 種ごとの「生息地が最低数ぎりぎり」のシード | 種ごとに 5%以下 |
| 生活の動線の分布 | 上限を超えるシード 0、平均が上限の6割程度 |
| **会えるまでの日数**（下の自動探索で測る） | §8.6 の目安以内 |
| 星の多様さ | 似すぎたシードの組が少ない（下記） |

**会えるまでの日数の測り方**：自動で歩き回る「探索役」を用意し、30日分の天気を生成して、各種の生息地を条件の合う時間に訪れたとして、実際の出現の計算（`CreatureSystem.Spawning` と釣りの出現モデル）で最初に出会う日を数える。地形に生息地が「ある」だけでなく、**本当に出会えるか**を確かめる。

**星の多様さの測り方**：各シードから「村の位置（水の旅のどこか）・湖の種類・海の近さ・段の数・山の形・名物の地域」などの特徴を取り出し、特徴の組み合わせの分布を見る。一つの組み合わせが全体の3割を超えるなど、偏りがあれば生成を直す。

**人の目での確認**：毎回ランダムな50シードの上から見た地図を一覧にして、面白い・つまらない・似ているを人が見る。数値だけでは「面白さ」は分からないので、ここは必ず人が見る。

**固定シードの比較**：代表的な10シードについて、生成結果の要約（ハッシュ）を保存しておき、同じ生成バージョンで結果が変わったら知らせる（再現性の確認）。

### 12.4 実機での検査（段階C）

今の `Tools/Unity-Check.ps1 -Mode Smoke / Visual` の仕組みに乗せる。

- 20シードで地上を作り、主人公を自動で各地域へ歩かせ、たどり着けるか（坂・橋・段差の当たり判定）。
- 住民を道路網で各地へ歩かせ、引っかからないか。
- 各地域で斜め見下ろしのカメラから撮影し、プレイヤーが地形に隠れていないか、画像を確認する。
- フレーム時間を計る（遠景・木・水面の負荷）。

```
 |       \       ||                 ****        |
 |  湿った森 ##   ||  こだまの谷               |
```

- **暮らし**：村の中に橋が2本と飛び石。毎日の釣りは村の川（F001・F003・F005・F013）。釣り好きの住民は橋の上で釣る。湖は「つづら折りの本道で行く遠出」。
- **名物**：こだまの谷（コダマル・カベピタ）、湿地（ヌマプニ・コケコロ・F004 ヒゲタマ）、段々の住宅地（ヤネコロが見やすい）。
- **会いにくくなる種と保証**：湖の魚（F046 カガミヌシなど）は遠出が必要。高原の湖は山に囲まれ風が弱いので、無風の日は多め。
- **修理用の魚**：F008 シモマダラが村の上流の淵（広場から本道で約25秒）。

```
  T=峠（海への本道） L=大きな湖 W=滝 M=鉱山入口
```

- **骨格**：南の山から滝が**盆地の大きな湖**へ注ぎ、村は湖の北岸にある**湖畔の村**。湖から流れ出る川は北の尾根を切る谷を通って海へ。海は**尾根の向こう**（峠道を越えて約45秒）。
- **気質**：霧が多い・盆地なので無風の日が多い・雨はふつう。
- **暮らし**：毎日の釣りは湖（F007・F010・F012・F015・F022）。湖の桟橋は最深部の近くまで突き出る（F046 を狙える立ち位置）。海側にも、沖まで届く桟橋が尾根の向こうの浜にある（§2.9）。霧の朝は村から湖が見えなくなり、霧の中に F040 キリガクレ。星の光帯の夜は、湖に突き出た岬の上の見晴らし台（段3）に住民が集まる。静かな高台は南の山の肩にあり、光帯の夜でも静か。
- **名物**：伝説魚 F046 カガミヌシ（無風の日が多い）、苔の古い森（モリマル・トビカサ・エダミミ）、霧の窓のマルマド。
- **会いにくくなる種と保証**：海の魚と浜の生き物は「峠を越えた遠出」。F038 カゼウケ（強風）は盆地では少ないが、海岸は風が強まるので海で会える。強風の最低頻度も守る。
- **修理用の魚**：R03 は湖の深場の F044 ヒヤシウオが村から近く、R06 は湖の静かな南岸に F043 オトナシ・F030 ハモリウオ。

### 13.3 シード C「風の岬の段丘村」

```
 北
 +----------------------------------------------+
 |  ~~~ 海 ~~~  |   高原 **** 花と風の野 ****   |
 |  ~~~~~~~~~~  |   (L)高原の池  Q静かな高台    |
 |  ~~~ 岬 >>   |                               |
 |  ~~~~~~ 崖 ##|=段3= [ 村 P h h ]  ^^^ 山 ^^^ |
 |  ~~~~~  入り江 |=段2=  h h h h   M ^^^^^^^^  |
 |  ~~~ W滝が海へ |=段1= 畑F H     渓谷 ||      |
 |  ~~~~~ 桟橋 |= 浜  ......  湿った森 #### ||   |
 |  ~~~~~~~~~~  |  不時着地X      ######  W2  |
 +----------------------------------------------+
  段1〜3=海に面した段丘 W=海に落ちる滝 W2=森の滝
```

- **骨格**：西の海に面した**崖の段丘**に村がある。山は東にすぐ迫り、川は短い。渓谷から湿った森を抜け、**滝になって入り江の海へ直接落ちる**。湖は北の高原にある**小さな高原の池と湖**。
- **気質**：風が強い・星の光帯がよく出る・雨は少なめ（最低頻度は守る）。
- **暮らし**：段丘の村なので毎日階段がある。そのかわり段差を飛び降りる近道が多い。桟橋と浜は段丘の下、釣り小屋は浜にある。広場から海が一望でき、夕方は F014 ツノサキの群れが見える。星の光帯の夜は、段丘の最上段の崖の縁にある見晴らし台に住民が集まる。
- **名物**：風の野（フワタネ・タネパタ・F038 カゼウケ）、海に落ちる滝（滝つぼの F011・急流の F023 が海のすぐそば）、高原の池のムレピカ。
- **会いにくくなる種と保証**：湖が小さめなので、湖の魚は「高原への遠出」。ただし湖の最深部・静かな岸・広い水面は**予約で必ず作る**（小さくても §2.3 の最低条件：差し渡し90m以上・最深部8m以上【仮数値】）。雨が少ないので、雨の生き物は雨の日にまとめて探すことになる。
- **修理用の魚**：R03 は渓谷の淵の F008、R06 は浜の F045 サザナミメ（村から近い）。

### 13.4 3つのシードの違いのまとめ

| | A 段々谷 | B 湖畔村 | C 岬の段丘村 |
|---|---|---|---|
| 村の位置 | 川の中流（川をまたぐ） | 湖の岸 | 海に面した崖の段丘 |
| 毎日の釣り | 川 | 湖 | 海・浜 |
| 遠出になる水域 | 高原の湖 | 尾根の向こうの海 | 高原の湖 |
| 毎日の移動の特徴 | 橋と飛び石 | 平らな湖岸の道 | 階段と飛び降りる近道 |
| 天気の性格 | 雨がやや多い | 霧・無風が多い | 風が強い・星空 |
| 名物 | こだまの谷・湿地 | 霧の湖・苔の古い森 | 風の野・海に落ちる滝 |
| 星の光帯の夜の集まる場所（見晴らし台） | 村の東の段3 | 湖に突き出た岬の上 | 段丘の最上段の崖の縁（海を一望） |
| 静かな高台 | 北西の山の肩 | 南の山の肩 | 北の高原の奥 |

どの星でも魚50種・生物50種すべてに会える。違うのは、**何が毎日の景色で、何が遠出のごほうびか**。
